# 原图皮肤、完整颌部与浅凸眼睛返修

适用于已有源图的鱼类材质与形体返修。方法实现见 Foundry `resources/runtime/godot/surface-chart-112/README.md`，物种数据见 `resources/volume-fish/*112.json`，本轮实机证据见 Fish `experiments/blender-fish/material-shape-112/`。112 是已安装的审阅候选，用户逐鱼外观确认仍 pending。

## 先定位来源

- 黑色可能来自源描边、鳍足迹、旧正面投影、口腔色或不透明回退；不是看到黑就断定模型大于贴图。分别看灰模、原色、皮肤单独显示、原图坐标探针及实际 shader 链。正常物种斑点要保留。
- 背面重复一行像素会拉丝。需要补隐藏皮肤时，使用原图二维像素块与拼缝，排除鳍/描边/眼/嘴。背、腹供体分别约束源图对应半侧，保存逐像素供体坐标并检查游戏多视。来源仍是美术延续，不能称实测背纹；无鳞鱼不凭空加鳞。
- 巨骨舌鱼112的第二个眼来自正面渐变叠层。用眼纹故障色投影定位后只处理该特征，保留原17档alpha融合、鳃盖和下层实体。不能把相邻大鳃盖当重复眼，也不能把整个装饰层强制不透明。

## 形与图分别约束

- 下颌本来就有尖角，不是保留它的理由。先看同种吻部资料和无贴图模型；移走尖点而保留完整下颌的错误轮廓仍是失败。110梭鲈被用户否决，不作推荐嘴型。
- 冻结原图内部上下唇线、嘴尖、口角、下巴与额头；不要把外alpha描边直接当口裂。局部形变按与口内共边相连的上下颌组件分区，不能按水平Y线分。若需要重做完整前颌，公共皮肤/口内边必须共享坐标、连续有向闭合，并保留后身、鳍、绑定和动画。
- 新旧头部窄窗拼接会鼓包或条纹。检查接合值、切线与定制法线；黑鲷112改为较长的完整额头过渡。张口截面中的名义椭圆半径可能落在空隙，不能当实际皮肤半宽。横向门的目标须在测候选前由参考约束确定，保留旧尖头负例。
- 唇线的像素误差只在人工标注支持区内有意义；超出端点的样条外推不能冒充参考证据。正、俯、斜视的完整颌部仍需实际审阅。

## 眼睛与验收

- 浅凸眼盖须贴实际身体面，插值实际骨权重，并映射 Godot 实际骨名（可能有 `_2` 后缀）。保留其下完整不透明皮肤；已有立体眼睛不重复叠盖。高度与未知厚度是美术选择。
- 变过几何的未审核LOD应明确排除，不能说原粗档已修好。绑定当前完整数组、LOD、shader与配置哈希；不能只看GLB哈希。
- 实际鱼可能使用私有控制器及展示缩放。鳍检查的plan应冻结该控制器与哈希，使用 `export_runtime_fin_roots112.gd`，不能用默认控制器冒充。完整鳍根177姿态，每次几何修改还须适用的490全鳍面及GPU身体门。
- 112真鲷在默认检查通过后，实际控制器暴露胸鳍自由面微穿入；修自由面，冻结根带原位保留，不提高0.02mm界限。离散姿态不是连续时间证明。

## 提交与清理

分别提交 Foundry 通用工具/skill 与 Fish 运行资产/物种记录。保留冻结输入、最终哈希报告、关键实际截图和失败结论；清理逐姿态网格、重复工程、旧回滚副本及密集重复截图。原报告不可偷偷改成“所有图仍保留”，用保留清单说明历史捕获数量与实际存档子集。字节哈希绑定的文本要明确Git换行策略，并在暂存后核对实际blob；提交授权不等于外观接受。
