## R5 用户接受并安装

2026-11-17 用户接受当前口部、眼片和两套捕食动作，并指定后续动作从本版继续。正式源、GLB、两段回放及检查索引见 [release-r5.json](release-r5.json)。Foundry 的 [r5-preview](r5-preview/) 保存独立 Godot 回放代码和物种配置，复用 [VolumeFishMotion.gd](../../runtime/godot/VolumeFishMotion.gd)。R4 记录与 `release.json` 提供历史定位。

用 Blender 后台运行 `repair_r5_source.py -- <R4 fish.blend> <输出目录>` 可生成候选源与 GLB。从 Foundry 根目录回放时，给出候选 GLB 和预览输出的绝对路径。

```text
godot --path resources/volume-fish/great-hammerhead-feeding-20261116/r5-preview --script res://capture_feeding.gd -- <fish.glb> <输出目录> video large
```

最后的 `large` 改成 `small` 回放小猎物分支。

- 碎眼在两侧实际 Godot 画面中复现。R4 眼面与邻近头翼的最大遮挡分别约 7.36 和 7.33 毫米。R5 将整个原眼图表与实际头翼三角面投影求交，两侧各 60 个正面三角，沿原眼中心和尺度封成浅眼片。侧投影最小外露 0.45 毫米，两侧 1,152 个交区顶点无头翼遮挡。回位侧视及全开斜视均用同机位比较。
- 身体 077 预检定位到一片口内衬里法线朝反。修正该面角法线后，较小的法线往返误差也记录在保留性报告。原上下颌支点、口裂、全部体表位置、UV、权重、内嵌图像及原生动画通过逐面角核对。最终 4,668 三角、22 骨、8 鳍，展示体长 400 厘米。
- 大食物从实际上下口沿构造夹持方向，收口时保持中央接触，尾端做滞后跟随。躯干用平滑起落的变频弯曲，混出时最多使用 88% 捕食姿态，尾段跟随延迟 218 毫秒。小猎物沿开口进入口内，通过后下颌回位。它们是本鱼动画制作值。大食物结束于衔住，包含夹持和处理动作。
- 已复核正式源冷导出逐字节一致、普通 490 姿态的完整鳍根和鳍面及同批 072、身体 077 两姿态八向。大小分支各有 253 个实际 Godot 捕食样本，另含静止及 25 个原生姿态的鳍根/鳍面检查。实际口腔/前头外壳专项两支各 254 姿态无自交。两段 60 fps 视频各 504 帧。正式首次/缓存、四动作画面、480 控制/360 切换和 96 次上唇挂钩通过，正式运行时 SOP 通过。完整资料、形态、唇域和部分展示证据待验。

复用整眼图表与实际有限头面求交的方法时，逐鱼重定眼域、支撑面与近景，复核闭合眼片和侧向遮挡。捕食时序及尾段响应由本物种配置独立决定。完整口腔与鳍的离散样本用于候选验证。见 `repair_r5_source.py` 和本机交接记录。
