# 112：源图皮肤、唇线与微凸眼睛

本轮是已有接受原图的返修，不是新的生图资产接受记录。正式游戏内仍显示“待你确认”；技术门不等于用户接受。

## 方法与参数

- `build_surface_charts.py` 从实际身体 UV 足迹、鳍足迹和描边排除带建立干净供体。背、腹分别限制在源图身体的对应半侧，排除眼纹与明确口部区；用原尺寸二维像素块和最小误差拼缝运输纹理，不把一行侧图拉成整个背面。输出逐像素原图坐标，不能把黑色一概当错误。
- `BodyChart112` 在原材质之后显式包裹。截面弧长来自实际身体三角形；保留侧面与真实眼区，单独处理尾柄端面。原 GLB、原图、骨架和动画均不由此改变。
- `rebuild_source_head.py` 用冻结的原画内侧唇线重做黑鲷、真鲷、梭鲈的完整前颌，保留后部、鳍、绑定与动画。上下唇和口内衬共边，检查闭合、有向边和灰模；前端留实际宽度，不能再收成单点。名义椭圆半径若位于张口空隙内，不等于可见皮肤截面的最大半宽；横向门用原图曲线解析得到的有效包络，保留旧尖头负例。
- `warp_source_lips.py` 对其余五鱼沿真实口裂调整既有完整颌部，保留横向坐标、拓扑、绑定和动画；按与口内边界相连的上、下颌组件分区，不能用一条水平线判颌。共享坐标族必须一起变形；法线按形变雅可比处理，不能丢掉原有平滑法线。
- `SourceJaw112` 关闭已失效的旧口部投影，使用新 UV 的源唇缘与口腔像素。口缘、皮肤和深处分别表达，身体材质不使用 alpha 裁切。
- `FrontSkin112` 仅对带鱼、孔雀鲈、蓝鳃太阳鱼冻结的前端皮肤选区运输不透明原图像素；牙、口内衬和几何保留。采样原 PNG 解码像素，避免把 Godot 对无关透明边 RGB 的导入修补误认成供体变化。
- `build_eye_relief.py` 在实际蒙皮身体上建立浅凸眼盖，插值真实骨索引和权重；原不透明身体完整保留。银龙鱼、食人鱼和双髻鲨已有立体眼睛，予以保留。高度是美术选择，不是角膜实测。
- `FeatureOverlay112` 只移除巨骨舌鱼 17 档正面融合贴片里的第二套眼纹；红色眼纹探针证明其投到真眼后下方。保留原透明融合、鳃盖及独立不透明身体。此模板明确绑定该原图/模型，椭圆不是跨鱼种参数。

物种输入在 Foundry `resources/volume-fish` 及本次归档的冻结输入中；游戏中对应 JSON 是运行时绑定，不能给另一条鱼直接套用。

## 验证边界

`ValidateSurface112` 重建精确的 shader 包裹代码，核对原始静态/106/107/104 管线、当前模型、完整数组、被排除的未审阅 LOD、配置、供体与实际 uniform。未知 shader 不接受。附加眼盖单独核对后隐藏，GPU 覆盖门证明其下面的身体独立完整；巨骨舌鱼装饰层不能被当成不透明实体。

`export_runtime_fin_roots112.gd` 是标准导出器的显式控制器版本：计划冻结实际游戏为该鱼使用的 controller 路径和哈希。黑、真鲷的展示缩放不能被默认根控制器忽略。标准导出器不变，两个阻断命令可用 `--exporter` 选择此版本。

完整鳍基仍须每鱼 177 姿态；本轮改几何的八鱼另做 490 姿态全鳍面。真鲷原生摆动还暴露了微小胸鳍自由面穿入，修订只移动自由面，完整冻结根带、UV、权重、动画及自定义法线保留，不放宽阈值。

原图唇线的数值检查只在手工标注的 X 支持区间内成立；末端卷唇超出标注处不能拿样条外推冒充新参考。体型横宽、隐藏皮肤和原图未给出的正面仍含美术推断。最终需要同姿态原图/灰模/贴图与真实游戏四动作及切换审阅。

## 存档与当前文件复核

Fish `material-shape-112/README.md` 是运行资产、冻结输入与保留证据入口。`verify_installed_fish112.py --game ... --archive ... --report ...` 核对实际132个安装文件、23鱼模型、材质依赖、最终鳍/身体报告及存档文件哈希；它不重跑GPU，也不作用户外观批准。捕获重放入口为 `capture_surface_mouth_audit.gd`、`capture_transitions112.gd` 和 `capture_review_hall112.gd`，避免依赖已清理的暂存工程脚本。

## 114：背腹贴图固定到原始网格

112的`chart112_rest_position=VERTEX`和`chart112_rest_normal=NORMAL`实际上读取了Godot Compatibility已蒙皮的输入，静态截面和法线掩码随游动改变，导致贴图滑转。`RestSurface114.gd`直接读取当前实际导入ArrayMesh的逐surface原始XYZ、normal、UV；RGBAF无mipmap、无sRGB转换表通过VERTEX_ID定位，并核对顶点数量/有效位/原UV。代码在任何chart计算之前恢复固定坐标；正常骨骼变形继续进行。查表错误显示洋红，不删除身体像素。

每个chart surface拥有独立ShaderMaterial，表不写进共享材质。复制须保留SourceJaw的显式禁用参数；Godot的duplicate不会复制已被眼域wrapper去掉声明的inactive参数。先核对旧材质为false，再恢复新材质为false，身体门继续严格检查，不能删除这个断言。

`ValidateSurface112`精确重建新的wrapper，再重算实际导入模型的完整surface数组、LOD摘要及三个表的全部字节、格式、尺寸和数量。SourceJaw和FrontSkin自身算法不在本次修复范围；FrontSkin外层继承其下的BodyChart修复。它们的UV画布诊断覆盖不足，不能用零变化当稳定性证明。

复现用`probe_material_anchor114.gd`：同一固定UV画布中实际生产vertex对照独立静态oracle；强制1000个非均匀供体像素，空命中失败。`legacy`参数仅在诊断内恢复原两条错误赋值，作为单变量负例，不写生产材质。`probe_runtime_anchor114.gd`保留实际LOD和真实3D蒙皮，覆盖四动作、三距离及四个真实切换中点。源图标线由`capture_original_lips114.gd`直接显示112原始PNG，源图与模型保持原样；标线不是嘴型或材质接受。
