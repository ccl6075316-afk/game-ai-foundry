# 置景原画到三维：正交视图方法

用户于 2026-10-24 指出：当前拼贴正面尚可，但场景物体需要原画、侧视和俯视来判断真实空间形态。单张轮廓鼓起后贴正背绘制的 V2 只是验证，不能当通用实体建模方法。

## 固定对象与坐标

先固定一张完整原画、对象身份和目标尺度。X 为主长度，Y 为竖直高度，Z 为前后厚度。正面相机从 +Z 看 -Z；右侧面从 +X 看 -X；俯视从 +Y 看 -Y，图上方为对象后方（-Z）。三视图是同一个对象的投影，不能分别当作三个相近设计。

为每个对象记录少数可识别结构点：岩石的高肩、阶台、凹口、贯通裂缝；沉木的根杈中心、每条分叉点、破损端、支撑根落点。原画是观察证据，未显示的深度先记为未知，不能把生出的第一张隐藏面当成已知真值。

## 生图顺序

1. 完整单体原画约束绘制风格与对象设计。
2. 生同一对象的正面、右侧面、俯视。优先先作无材质灰模/线稿三视图，让相机、遮挡和分叉关系可读；可以把三视图放在同一张板上共同生成。
3. 实际看图识别每个视角。文字标签、技术图像验证或文件名写着 TOP，不证明相机正确。俯视不能继续展示大面积正面立墙；沿长轴的端视不能继续展开整条长枝的侧身。
4. 相机和结构对应通过后，再生成保持该视角和轮廓的正式像素绘制图，作为贴图供体。材质和结构审查分别记录。

Foundry 的 `project.view` 应按实际任务设置。混合三视图板不应注入统一侧视模板。图像计划需检查最终 prompt，避免 `character` 模板的单主体/侧视，或 `background` 模板的环境场景/禁止白底，与技术板要求互相矛盾。需要时将已有 handoff 的 prompt 改为完整人工技术说明；不能只检查原 Brief 文案。

## 识别和校准

- 正面宽度与俯视长度对应 X；正面高度与侧面高度对应 Y；侧面宽度与俯视纵深对应 Z。
- 比较共同坐标下的结构点和轮廓跨度。若纸面缩放不同，记录每张图的统一比例，不能分别非等比拉伸以伪造一致。
- 在俯视中，垂直向上的树枝应明显缩短为近似端面，水平支撑根的前后分布应展开。在端视中，沿长度方向的主枝应遮挡/缩短。
- 图像尺寸/主体区域检查仅作辅助。还须人工检查遮挡顺序、枝杈数量、对象身份、凹口方向和相机。相互矛盾则回到图像修正，不先搭模型去迎合矛盾输入。

## 建模与贴图

三视几何可信后才建共同体积，轮廓从三向包络共同约束；树杈从同一组空间连接点建立连续实体。不能将三张整图分别贴成互不关联的板，也不能仅给原有单图鼓包模型补两张颜色贴图。

源图像素保留。为实际表面建立投射/展开和供体归属，明确正面、侧面、顶部、背面及接缝来源。未有来源的区域保留待补，不通过拉伸一个边缘色带声称覆盖完成。

在实际 Godot 中检查灰模三视、贴图三视、斜视、完整绕转与不同受光。报告需明确技术通过范围和操作者实际看图结果；用户最终认可单独记录。

水草同样需要整株侧/俯关系来安排根茎、叶柄与叶片方向；独立生成叶片只能提供单片形状和纹理，不能替代整株空间姿态验证。
# 材质试作补充：跨度相近仍可能对应错误

V3 沉木的三个包络宽高接近，但主枝在端视中的高度低于正视/俯视所需位置，硬取三轮廓交集会削掉主枝。不能用“约 8% 深度差”证明几何成立。当前 `three-views-v3.json` 明确端视为 `depth_only`：正面 medial 半径、俯视人工深度引导及占地限制只用于**待审核材质试作**，不是三视精确重建。原图、引导、投影残差、失败原因和游戏灰模必须一同保留。

正/俯轮廓的直交体会产生板状外形；逐 X 椭圆区段配对会在根杈的区段切换处断开。不要把技术闭合当成自然体积。当前生产前仍需重新校准各断头、分叉中心和根足，再补相互一致的端视。彩色重绘会重新引入斜相机，不能反过来覆盖已查验的灰模轮廓；保留为颜色供体时需明示缺陷。
