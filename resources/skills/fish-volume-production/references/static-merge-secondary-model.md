# 旧鱼 Godot 静态装配迁移：次级模型执行卡

适用范围仅为生产 SOP 0.2 中的**本地静态迁移检查点**。新鱼、主动修鳍/改拓扑/减骨和正式鱼资产交付仍走完整 SOP。以下是红帝鱼 169 与海鲈鱼 170 的实测方法，不把某鱼的网格数、LOD 数、纹理表或姿态结论复制到别的鱼。

## 开工冻结

1. 对单鱼记录旧安装 GLB、实际入口脚本、装配前与装配后 AABB、可见网格/表面/材质/蒙皮/骨骼/原生动画、每表面 LOD。旧入口实际显示值才是基线；脚本名和 GLB 原始网格不是基线。
2. 外部模型读取私有文件须有有效授权；复用用户已给出的持续授权，不逐鱼重复询问。用户于 2026-10-29 明确允许 PI 查找、处理及发送本工程任务所需内容，后续依此执行，直到用户收窄或撤回。API 密钥只从本机配置或环境读取，不写入提示词、日志、报告或提交。
3. 先保存旧 Godot **导入后的原生 Animation** 和逐表面 LOD 数据，再替换安装文件。海鲈鱼曾在 Blender 中逐帧动作完全相同，Godot 重新导入后仍出现约 `0.00217` 骨骼姿态差；旧原生动画引擎资源复用后 59 帧最大差 `7.75e-7`。不能只比较 glTF 原始 channel 或 Blender 曲线便认定引擎动作相等。

## 分门交给次级模型

每次任务只做一个可验收门，给固定输入 SHA、指定鱼、指定输出和失败退出条件；主模型不接收“已完成”的口头结论，而读取报告并抽查关键数组与画面。海鲈鱼实测顺序：旧实际装配 → Blender 可编辑源与重导出 → Godot 几何/蒙皮/59 帧动作 → 旧 LOD 精确转移 → 旧材质冻结 → 顶点查表重排与冷读 → 真实入口同相位画面。每门通过再开下一门，失败报告保留差异值。

子进程须有硬超时（本机 Godot 90 秒），为 Godot mono 配置 .NET 路径；所有日志、临时项目和输出仅在本实验目录。搜索限定到具体文件或子目录，用 `rg`，不要递归扫描整个 Foundry。保存每次模型调用回合、工具调用和 API 费用；API 费用不等于 Codex token 净节约。

## 导入和画面门

- 重开 `.blend` 后能重导出当前候选；同姿态逐三角形检查几何、UV、骨名/权重，另用 Godot 实际导入比较。小权重导出阈值如需进程内修补，必须在报告中注明 Blender 版本与再生验证。
- 对旧实际 LOD 的每一层比距离、索引代表的三角形与朝向。新旧顶点编号可能不同，按位置、UV、法线及骨名权重映射；身体/眼睛旧终态无 LOD 时只按本鱼哈希去掉新自动 LOD。数量相同不足以通过。
- 搜索**全部**当前 shader 的 `VERTEX_ID` 查表。用 Godot 新导入顶点顺序重排所有相关浮点纹理，检查格式、mipmap、alpha、padding 和每个有效 texel；不要只查 `rest114`。UV 查表另按其实际索引语义处理。
- 旧入口若以装配前 AABB 归一化，新静态 GLB 需按相同旧边界在本鱼哈希分支下恢复尺度。旧新代表画面必须同控制器相位、机位和模型/载体变换；旧 Swim 三视与新四动作加切换三视均完整入镜，并由执行者实际看图。
- 主工程合入后再用新进程冷读、重拍。只将通用方法写本卡/SOP，物种参数与 SHA 留在该鱼资源及报告。旧专项报告标记失效；完整鳍专项和 `volume sop-check` 留在正式候选冻结时执行。

## 2026-10-29 对照后的补充

- 选鱼前核对远端最新检查点，避免本地旧提交导致重复迁移。草鱼175、虹鳟176本地检查点已完成，不再作为待处理鱼。
- 虹鳟实际有脂鳍、19骨与18轨道；材质第二面是`material139_positions`，不能复制草鱼的`material130_positions`。实际冻结报告优先于任务预期。
- 已证明窄门可交PI执行：旧装配冻结、源导出与原始法线保留。虹鳟四门接口报告约$0.266、含两次超时，尚未证明端到端时间或Codex额度净节省。
- 避免新增不可靠的字符串验证器，shader可能通过先前变量间接索引。保留真实索引链和实际texel核验。绑定器生成只替换精确常量/断言，不要求普通重复标识只出现一次。
- 超时先读落盘结果，已通过门继续复用；Godot的`assert`后可能仍运行，进程包装应在`SCRIPT ERROR`出现时停止，不仅靠90秒超时。
- 用量分开记未缓存输入、缓存输入、输出、次级API费用、模型执行秒数、主执行者接手范围和返工；换模型及同步开销必须注明，不能用整数额度差直接宣称节省比例。
- 自动提取的PNG及`.import`可能仍被`.scn`引用，应作为引擎依赖保留。仅称其“可重建”不足以删除；若删除，须完整重建依赖并在新进程冷读。2026-10-29曾删除后从GLB原样恢复六张PNG，最终六条旧鱼冷读通过；不要重复此清理错误。
