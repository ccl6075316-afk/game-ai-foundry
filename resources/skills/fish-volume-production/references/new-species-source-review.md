# 新物种生图与源图拆分排错（145）

本页补充生产SOP阶段1、2、3、7、10。侧影/HTTP/GPU排错另见 `side-projection-review.md`。这里沉淀检查方法，具体鱼的参数、候选通过状态仍以本鱼账本为准。

146纠正：145太平洋蓝鳍金枪鱼的嘴部/背腹外观审核被用户指出错误，原操作者通过结论不能继续作为这些部位的基线。实际模型没有独立薄唇带；小口裂/倒角不能替代既定135/140流程。背部供体包含侧身点斑，头下方有侧面深描边绕投。原始技术报告保留其技术范围，不能据此继续宣称整鱼外观接受。返修状态与取样证据从 `projects/pelagic-fish-146/` 的validation读取。

| 遇到的问题 | 应怎样处理 | 必须留下的验证 |
|---|---|---|
| 物种俗名含混，或资料对学名采用不同分类 | 先固定用户指定物种与海域；记录资料的分类差异，不在制作中悄悄换种。大西洋旗鱼的 albicans/platypterus 分类处理与太平洋蓝鳍金枪鱼 orientalis 分别记录 | 同种资料卡、用户澄清、形态约束、未知项 |
| 图像好看但局部解剖错 | 源图审核先数部件，再核对比例和位置。例如蓝鳍金枪鱼胸鳍长度、第一/第二背鳍高度及上下离鳍数量；旗鱼腹鳍与胸鳍长度关系 | 带编号的原尺寸标注、失败源图及修订理由；重新接受实际使用的版本 |
| 俯视/腹视生成了侧身图或把帆鳍平摊到两侧 | 按实际图像判断视角与用途，不能按文件名相信视角。拒绝作为几何或完整表面材料；若仅作局部皮肤供体，另审明确区域及排除区 | 全图实际查看记录、用途/拒用状态；未使用的图不得出现在最终材质来源中 |
| 二维鱼图并非展开的完整三维皮肤 | 先明确身体与独立鳍的归属，身体背腹使用原尺寸安全皮肤块的二维补纹/曲面图。隐藏皮肤是美术补全，不冒充真实观察 | 原图、供体、目标/排除掩膜、映射和补纹报告；隐藏全部鳍后的多视图 |
| 从鳍的独立裁图直接套用旧的全图UV统计 | 独立裁图UV是局部0–1，与身体全图UV不是同一坐标域；必须保留原图裁框/变换，用原图鳍多边形清理身体足迹 | 原图SHA、裁框、像素尺寸、RGB逐像素相等、alpha只保留或清零、实际UV映射；不能重采样后称原像素 |
| 鳍清掉后连身体上的鳍根痕迹也消失 | 活动鳍与身体拥有的连接痕迹分开。补纹后只恢复经原图确认、位于身体一侧的原生色块，不能把整片胸鳍画回身体 | 两套归属掩膜、鳍隐藏图与完整模型；不确定组织名称就保留未知 |
| 沿轮廓标点却用长直线跨过弯曲凹口，产生交叉 | 建模前检查原尺寸多边形边界，沿实际弧线补点；不要把自交的尾鳍多边形当合法轮廓 | 原图叠线、交叉负例、闭合/退化检查及最终GLB检查；Blender内部拓扑正常不能替代导出后检查 |
| 鳍根端点贴住了，边与面仍悬空或穿体 | 完整根带冻结在修复前；保持全部原根区，按曲率细分接触区并匹配实际身体蒙皮。修后查177姿态、490全鳍面、源形状及实际可见范围 | 原始失败报告、完整选区、保留的远端/UV与根带变化、实际同姿态距离。不得以缩小根区、关鳍动作、放宽容差通过 |
| 先在源二维平面无限加密，再把整片根区压到同一曲线 | 对称/邻近点可能重合，形成折叠或焊接后非流形；这种失败候选不能升为通用模板。检查导出GLB几何后再选择实际曲面接触细分方法 | 导出后焊接/退化负例；源形状、蒙皮和完整根区的复验。145c加密尝试是失败记录 |
| 长吻鱼的口裂切割穿过整条长吻 | 分开定义真正口角/口裂前端与上颌长吻端点。长吻是物种固有上颌延伸，不能用普通鱼的追加尖鼻修法；静态口裂通过不代表开合颌通过 | 侧源标志点、真实资料、灰模正侧俯斜、口内闭合与身体077门；原有非长吻鱼行为回归 |
| 前吻补色把长吻端也涂成下巴色，但头部根本没有有效选区 | 先判断投影分支是否适用。旗鱼的朝前端面主要是长吻尖端；不能拿这个法向当额头。145尝试有界投影后探针覆盖为0，已删除该无效分支，保留源图长吻材质；金枪鱼独立审核 | 长吻正/斜视、有效覆盖探针与实际绑定；不能把零漂移但零覆盖称为通过 |
| 前吻补色随蒙皮滑动 | 新鱼用 `immutable_rest114=true`，从当前实际导入顶点表取rest位置/法向，并在114初始化之后赋值；不能从已蒙皮的VERTEX/NORMAL取所谓静止坐标。旧鱼默认行为保留，分别回归 | 114图/前吻GPU探针、真实动作视频和实际LOD；使用旧坐标的负例须能检出漂移，共用helper的旧鱼还须冷进程像素对照 |
| 自动LOD把长吻折短、把头压成楔形 | 必须逐档强制显示实际索引缓冲，不能以正常距离暂时没看到为通过。修正简化约束，或为本次新资产明确选择完整模型交付；后者须记录完整模型性能成本，保留本鱼实际失败负例，不能照搬别鱼的退休例外、也不能称低模通过 | 全部旧档位负例、当前实际LOD清单、原生全细节三角形/蒙皮等价性、重导入后的114/077/动作视频。本次145只接受full_detail_only分支，不声称已有可用简化LOD |
| 脱离的长任务被宿主当作还没返回，或再次启动同一任务 | 长任务使用detach返回的同一job_id查status。脚本启动CLI时，把输出写到独立文件，避免后台子进程持有捕获管道；只从manifest/progress等状态判断 | 唯一job回执、状态报告；禁止重复run或把日志安静当成完成 |

源图审核接受、建模技术验证、局部返修验证、操作者视觉审核及用户接受是不同状态。新的候选只要仍有未通过的门，就保持相应SOP项目pending/failed；不能把本页知识条目当成整鱼验收。

顺序补充：先看源图与实际整片鳍、身体遮挡及灰模/头部，再启动昂贵的全姿态物理检查。单纯二维IoU不直接作所有鳍的统一阈值：需分清经身体表面贴合的完整根带、可见自由鳍、极细鳍条和成对鳍的空间展开；把差异标出来并解释归属，不能用“推断”掩盖可见自由鳍被截断。

## 已落地的通用入口

- Profile 的 `native_fin_cutouts:true`：Foundry `build_fish.py` 为各鳍输出带原生密度裁框的独立PNG/材质；`volume validate` 校验清单、裁框、尺寸、源RGB与仅裁alpha。身体清理另走 `build_source_skin140.py`，不能把鳍裁好等同身体已干净。
- CLI与Blender共用 `cli/volume_shape.py::validate_simple_fin_polygon`，在本分支的建模前阻断交叉、非相邻边接触及零长边。保留凹多边形；旧分支不被无条件追改。
- 静态长吻口裂用 `oral_jaws.bill_tip_u` 区分真正口裂前端与上颌吻端；目前禁止与独立下颌动作/前后颌位移混用，不能把它当做已验证的开合长吻实现。
- `FrontSkin112.gd` 新鱼target的 `immutable_rest114:true` 复用已绑定的114查找表；`ValidateSurface112.gd` 检查实际构造与参数。`probe_material_anchor114.gd ... <species> front legacy` 只在探针内恢复旧坐标作负例，不改生产资产。无有效前吻供体域的鱼不启用该分支。
- `validate_native_fin_bindings.gd` 检查原生已描边独立GLB鳍的实际Texture绑定、原尺寸、完整可见/蒙皮清单、不重复加描边、静止材质场与明确的完整模型分支。它接收冻结的物种/模型SHA/身体尺寸/逐鳍裁图尺寸plan并写JSON；不以旧“edge_count必须大于0”的检查器逼迫再画一圈。像素来源、完整接触和GPU身体门仍单独执行。

完整模型重新导入后，即便GLB字节没变，实际顶点顺序也可能改变。重新生成114查找表并验GPU；物理报告若保留，必须证明完整POSITION/蒙皮三角形、骨架、动作和控制器等价，不能只比较GLB哈希。145的原生全细节分支据逐三角形蒙皮等价证据保留490采样的物理意义，材质与覆盖另做新验。

原生基础体handoff与最终运行装配不是同一资产时，明确 `artifact_role` 和带路径/SHA的 `runtime_assembly`。基础体的风格接受不能冒充最终导出/安装，也不能使后续Agent绕过装配的SOP与专项门；从实际安装清单找当前版本，不按编号最大或某个accepted字样猜。
