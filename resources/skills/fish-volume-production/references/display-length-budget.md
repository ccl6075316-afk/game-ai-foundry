# 展示体长分档面数预算

## 2026-11-28 现行规则：面向 5 万条鱼同屏的「体长 × 形态复杂度」LOD0 与四级 LOD 预算（覆盖下文旧 2000 紧上限）

用户明确调整制作与运行时面数策略：**以 5 万条鱼同屏为压测上限，靠单材质合批（`Draw Call = 1`）+ GPU `MultiMesh` + 四级 LOD 控制总面数（全屏稳在 ~400 万面以内），源资产 LOD0 不再为了抠几百面牺牲近景眼球、鳃盖、嘴缘、鳍根或非扁片生物的立体轮廓与触手弯曲。**

确定性实现已更新在 `cli/fish_budget.py`：预算由 **展示体长档** 与 **形态复杂度起步档（`anatomical_group`）** 共同决定，**取两者中较高的一档**：

| 形态分类（`anatomical_group`） | 起步 LOD0 优选 / 硬上限 | 随体长继续升档（>300cm / >600cm） | 运行时自动 LOD1 / LOD2 / LOD3 | 典型适用物种 |
|---|---:|---|---|---|
| **`standard_lateral`**（常规侧扁鱼） | **4,000 / 5,000**（≤120cm）<br>**6,500 / 8,000**（120–300cm） | `8,500 / 10,000`；`12,000 / 15,000` | `400–600` / `120–160` / **`32–64`** | 鲷、鲈、鲤、鳟、沙丁鱼、金枪鱼、旗鱼、带鱼等 |
| **`shark`**（鲨鱼 / 软骨鱼） | **6,500 / 8,000** | `8,500 / 10,000`；`12,000 / 15,000` | `800–1,200` / `250–350` / `64–96` | 黑鳍礁鲨、各双髻鲨、鲸鲨（8m 适用 `12,000 / 15,000`） |
| **`dorsal_complex`**（俯视主导 / 宽翼 / 龟甲 / 繁鳍） | **6,500 / 8,000** | `8,500 / 10,000`；`12,000 / 15,000` | `1,000–1,600` / `300–500` / `96–140` | 海龟（蠵龟）、鳐鱼、蝠鲼、比目鱼、狮子鱼、海马 |
| **`multi_limb`**（多触手 / 多步足软体与甲壳） | **8,500 / 10,000**（不受小体长限制） | >600cm 升 `12,000 / 15,000` | `1,500–2,400` / `500–800` / `150–220` | 章鱼、鱿鱼、乌贼、水母、龙虾、螃蟹 |

- **不变的三条真正性能底线**：① 单网格单材质 **`Draw Call = 1`**；② 共享单套 PBR 贴图（常规侧扁鱼 `1024×512` ≈ 2 MB BC7、大型硬骨鱼 `2048×1024` ≈ 4 MB BC7、鲨鱼与俯视/多肢体生物 **`1:1` 方图 `1024×1024`** ≈ 3 MB BC7）；③ 骨架骨骼数克制，LOD1/2/3 全部共享同一套 PBR 贴图（零额外显存）。
- **“优选”仍不是下限**：已有合格且少面的成品（如 `2,810` 面真鲷、`2,852` 面黑鲷 R2、`2,858` 面海鲈 R2）绝不为凑数加面；需要做精细 3D 眼球、鳃盖/鳃裂、牙齿、俯视宽翼与触手环段时放心用到优选~硬上限区间。

优选不是最低面数，已有少面合格资产不为凑数增面；仍按最终完整装配统计并保留全部质量门。此次确认预算口径，不追认任何模型的外观、解剖、动作或交付接受。

## 2026-11-02 鲨鱼澄清：3000～4000起步，长体型继续增加

用户补充“鲨鱼3000–4000起，但是如果体长长就再往上加”。这规定鲨鱼的最低起步预算档，不是给所有鲨鱼统一封顶4000。当前确定性实现以3500优选/4000本档硬上限作为3000～4000范围内的起步取值，大体长档继续提高：

| 鲨鱼展示体长 | 起步/升级范围 | 当前实现：优选 / 本档硬上限 |
|---|---:|---:|
| ≤300cm（包括≤120cm） | 3000～4000 | 3500 / 4000 |
| >300cm且≤600cm | 5500～6000 | 5500 / 6000 |
| >600cm | 7500～8000 | 7500 / 8000 |

这里的“最低”指预算起步档；完整形体、嘴和鳍的需求决定实际面数，不靠凑数加面。体长升档后使用对应更高上限，不能继续套4000；正好300/600cm仍归前档。现有代码已按体长升档，本次澄清不需要改算法或重建现有鱼。

## 现有体长分档与鲨鱼实现

**2026-11-01鲨鱼例外的确定性取值（11月2日澄清为起步档）**：当前鲨鱼起步档取优选3500/本档硬上限4000，即使展示体长≤120cm；>300–600cm采用5500/6000，>600cm采用7500/8000，正好300/600cm归前档。不为凑数增加面；全鱼统计与全部质量门不变。`cli/fish_budget.py` 对现有五种鲨鱼有显式物种登记，新鲨鱼可由物种profile的 `anatomical_group: "shark"` 声明。交付门传递实际物种/分类，不凭名称包含“shark”猜分类。

用户于2026-10-31明确修改当前制作规则。按本鱼实际配置的**展示体长**，整鱼三角数采用：

| 展示体长 | 优选三角数 | 硬上限 |
|---|---:|---:|
| ≤120cm | 1500 | 2000 |
| >120cm且≤300cm | 3500 | 4000 |
| >300cm且≤600cm | 5500 | 6000 |
| >600cm | 7500 | 8000 |

“超过”使用严格大于：正好120、300、600cm仍归前一档。优选不是下限；已有更少面且合格的鱼不为凑数增加面。不因体长放松嘴、鳍、源画风、头型、身体不透明、蒙皮、动作或导出门。

计入身体、上下颌/嘴及口内、全部鳍的两侧/厚度/封边与所有附层；按真实最终导出/装配三角统计。使用项目展示尺寸，不能用物种自然最大体长、碰撞球半径、鱼缸大小、图片宽度或为预算临时放大的体长冒充。

确定性规则在 `cli/fish_budget.py`。源嘴/补色作者检查本鱼profile体长与声明上限，声明可以更严格但不能越档；完整交付门再对照geometry/motion展示体长及真实viewer缩放，计算当前模型三角并保存`budget.validation.json`。未知、非正、NaN体长不能自动取得高档预算。旧报告不追认，旧案例的2000限制保留其历史语境。

当前游戏配置例：大西洋鲑73.66cm仍为1500/2000；黑鳍礁鲨150cm、巨骨舌鱼200cm、路氏双髻鲨250cm、锤头鲨中的无沟双髻鲨300cm、旗鱼240cm、蓝鳍金枪鱼180cm适用3500/4000；巨型双髻鲨400cm适用5500/6000；鲸鲨800cm适用7500/8000。物种/命名以实际species ID和逐鱼清单为准，不由示例转移验收。
