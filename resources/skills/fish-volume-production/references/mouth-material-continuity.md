# 圆顺头吻、薄唇带与原像素唇线的接续

140用户复评：蓝鳃/罗非鱼139上唇取样区落到嘴缝/下唇，已作为失败定位；不能继续作为推荐源线。分别重标上唇外皮/内边、保留本鱼原画描边，并在灰模、单独带层和实际材质里确认有浅凸覆盖。当前修订参数入口为 Foundry `resources/volume-fish/fish-revision-140.json`。

薄带略凸不能只加顶点法线偏移。曲面上的三角弦仍可能埋入身体，检查带的全部顶点、边中点与面心；必要时做保持UV/原接头的相容细分，再将新增点投回实际皮肤并保留声明的浅凸。不得靠放宽门限、遮黑或扩大整个嘴来掩盖缺带。口角的surface分区边界可以有四叉接点，不能假定它就是单一完整口环；用已标本鱼唇域和实际皮肤共同定位。

用于侧图正确、正/俯/斜视却有横切面，或补出的唇线与原材质接不上的问题。黑鲷126—135提供单鱼静态证据；用户最后评价“好很多”并要求沉淀提交。隐藏宽度、中央纹理仍是制作推断，不能把该鱼参数或静态认可推广成全部鱼的交付通过。

## 先判断是曲面还是材质

同姿态、固定世界相机并排看灰模、无光照原色、实际材质和未清洗源图。不要让包围盒自动取景或独立裁切缩放遮住偏差。额头/眼前至吻端、上下唇、下巴分别检查：灰模仍有平面就先修几何；只有贴图显出竖黑线，追实际取样和空间归属。

**圆顺需要加减整个过渡域。** 只磨原端盖或向前追加小圆头，会留下新的平面、接缝或鸟嘴。允许填局部凹缺、消减突角，并在完整额吻域衔接曲率；不能为了避开黑色取样压窄眼前颅部。旧拓扑过长/过稀时先换适合表达曲面的布面方式。重新布面的灰模只证明形态方向，原UV、材质参考坐标、蒙皮和动作都须另行运输/验证。局部减去前端体积时用连续支持域；下方衰减太窄曾产生新下巴凹折。

## 薄唇按原材质定形

从真实皮肤/口内公共边和源图唇色带分别确定上下唇。保留口缝，不套整圈圆管。沿唇长冻结源图宽度、收束和未知中央连接；源图宽度先扣除轮廓倾斜，再以实际曲面行走距离铺带，不能直接以世界Y宽或UV拉伸代替。两侧已有宽度可延续到未见中央，但这属于美术延续。薄起伏贴实际体表并向边缘融入，不靠厚唇遮掉不平的头部。

## 修竖描边，同时接回真正唇线

侧图边缘墨线被宽吻投影到正中，会像竖着的人中。只修确认错位的竖向足迹；保留真正唇缘、嘴缝、鼻孔和正常暗纹。源UV孤岛上的碎掩码可能漏出黑孔，必要时用连续三维皮肤归属限定修复域。供体必须是确认的原皮肤块，不能只按“非透明”或全局黑色阈值判定。

“沿唇带补点”需要接续原画材质。133按几何边缘画光滑线失败；134裁出原图深色组件、再按世界弧长排列也失败。复制了RGB，仍可能丢失原线位置、整块形状、跨唇尺度与排列相位。

1. **测三个尺度。** PNG单像素、多个像素组成的绘画簇、曲面投影后的可见块大小各自测。134的纵向单像素换算接近实测，不能把失败简单归为像素间距。
2. **找实际接头。** 从当前实际身体材质追踪唇带下方UV、shader变换和opaque回退，再测唇层自己的UV；不能假定它们都用源平面坐标。本例局部相差约20源像素，中央旧图还重复同一列。
3. **上下外边界分别确认。** 下唇靠口缝的上边不能当下侧外边。确认线可能位于浮起唇带旁的皮肤上，不把它硬挪到带边。
4. **延续完整源图像素簇。** 接头冻结源UV、沿曲面弧长的导数及跨唇采样；中央图保留黑边、中间灰阶和唇色整块，不提取碎黑点、强制空隙或任意设置排列起点。保持原生分辨率与nearest。邻接皮肤与唇带必要时共享同一连续图，避免两条独立接缝。
5. **验证位置和显示。** 保存逐像素供体坐标、alpha回退来源及源图哈希；同机位、同ROI、共同nearest放大看接头与块大小。已知侧段UV零误差不等于未知正中颜色误差为零，供体RGB一致也不等于视觉自然。

## 实现时容易遗漏的细节

- 从冻结原始数组创建新ArrayMesh，别反复读取已量化法线再写回；一次无意的法线重编码就可能改变灰模。
- 换拓扑/顶点顺序后按实际surface重绑VERTEX_ID参考表，包括原材质坐标和眼表；“源材质参考位置”与“新模型静止位置”语义分开，未迁移绑定的静态网格不能声称可动。
- Compatibility的fragment sampler预算可能被眼、皮肤、嘴部表耗尽；135把上下共享皮肤图合成一张才通过实际GPU编译。退出码0不能替代完整日志和图像检查。
- 改几何后重新看原图、灰模/贴图正俯斜视及适用鳍/身体/动作门；仅改材质也须重验身体覆盖。静态研究可存档，不能据此安装或批量推广。

具体输入、反例、恢复命令与保留范围见 Foundry [135复盘](../../../../docs/anvil/knowledge/2026-10-23-fish-mouth-material-continuity.md)，Fish `docs/3d-fish/MOUTH-STUDY-135.md` 和 `experiments/blender-fish/lip-uv-alignment-135/retention.manifest.json`。复现包保存最终静态候选和必要输入；早期失败渲染代码只作该对照的依赖，不是推荐修嘴方案。

## 140：保留已可接受部位，并独立验证新凸带

先在未清洗原图标出真正上唇皮肤带，不能将嘴缝/下唇的采样折线当上唇。蓝鳃、罗非鱼139对应上唇参数被140替代，参数从 `resources/volume-fish/fish-revision-140.json` 路由。上唇浅凸、原黑色完整像素簇及实际接头一起验证；薄带顶点在外不代表长边/面内不埋入，必要时细分实际三角后再测。

用户暂留的蓝鳃、草鱼、罗非鱼下唇恢复139几何、原材质及身体相邻图集，并保存支持域未变的证明。140早期改动这些下唇的原型已撤回，不作浅凸模板；保留证明不等于旧下唇通过新接触门。梭鲈属于明确下根修复，新的下唇单独经过接触细分与实际引擎绑定检查。

使用 `closed_body_index140.py` 对按077精度归一的闭合体建立一致绕向分类索引；最近距离仍取未改写的实际身体三角。`test_closed_body_index140.py` 保存内/外、混乱绕向和分缝负例。最近三角法线点积及未经处理的混乱面绕向均不能可靠判内外。接触门不替代鳍177/490、身体GPU和视觉审核。

## 139推广实现的补充约束

这轮将完整方法参数化；物种参数位于 `resources/volume-fish/mouth-repair-139.json` 和 `mouth-curvature-rollout-136.json`，阶段与失败证据在 Fish `experiments/blender-fish/mouth-rollout-136/`。参数文件中的 `candidate_pending` 不是验收；最终状态必须核对当前报告和实际安装资源。

- `prepare_source_lips.py → build_source_lips.py → probe_source_lip_uv.py → build_mouth_material_continuity.py → transfer_mouth_skinning.py` 分别冻结原画色带、真实曲面弧长、实际外皮UV、完整像素簇及蒙皮。后缘若有四个同X点，按左右两侧选角点；不能误选同一侧的短边。曲面行走按累计实测弧长停止，不能只走固定步数再声称宽度正确。
- 唇色供体只取外皮，不能把共边附近的口内隧道UV当嘴唇UV。蓝鳃太阳鱼的旧极端端盖UV必须显式记为本鱼源坐标修复；不能把修复后的坐标写成原UV零误差。原画深色口缘是允许的原生色素，不能因低亮度就一律拒绝。
- 鼻端归属用 `extend_mouth_ownership.py` 在唇图旁打包，先恢复误投的皮肤、再叠原唇色。口内、真正鼻孔和斑点仍分别保留；没有确认错位时不全局擦黑。上部头纹淡出过早导致描边横向拉长时，只延续本鱼已有二维背部图到上部截面；不同时覆盖下巴/唇线。
- `RestSurface114`表存在，不证明所有surface都用到了它。实际139控制检查曾发现口内共用源图shader仍读已蒙皮 `VERTEX`；它没有112图，也要单独绑定静态位置表。`front112_rest/normal`同样必须改用静态参考。先通过实际物种控制器的材质/参数检查，再批量制作录像。
- 几何法线重算先核对源绕序与外向法线方向，再插值；混合相反法线会制造额头明暗断崖。源材质位置、几何静止位置、当前骨骼姿态三者不可混名。
- 跨目录冷加载发现 `FLAG_BUNDLE_RESOURCES` 仍可能保存导入缓存里的 `CompressedTexture2D`引用。用 `PortableMaterial139.gd` 将实际原尺寸图与RGBAF表封装为 `ImageTexture`，保留native像素和nearest；再从独立游戏目录加载并查全部实际sampler。网格成功保存或暖缓存截图正常都不能代替冷加载。
- 实际139资源身体门通过 `validate_body_integrity.py --mouth-runtime-report ... --mouth-candidate-plan ...` 执行：查实际替换网格闭合、逐surface材质/供体、16组同姿态GPU覆盖及真实骨名绑定。权重按Godot实际UNORM16编码逐整数比较，不拿原GLB身体或放宽浮点误差冒充新资源验证。原GLB只作为rig、未变部件和鳍的来源。
- 多鱼截图先保存全部固有可见性，每次切鱼都恢复该鱼的原可见状态；只隐藏其他鱼、却不恢复新选鱼，会拍出空白动作图。运行包装器必须拒绝任何 `ERROR:`，不能因Godot退出码0或图文件存在就通过。

孔雀鲈采用独立下颌/已有真实眼睛分支：修旧眼UV偏移、清掉原画完整眼圈（不仅虹膜），并单独退役错误的细长112眼盖；保留真正 `Textured_eye` 两眼。下层补皮肤要保留同Y原画明暗过渡，不能用一小块深色额纹覆盖整眼制造新眉斑。其首次完整鳍面门还暴露了旧接合埋入；根通过不等于膜面通过，相关候选未通过前不得交付。


## 146：原生嘴也必须执行完整唇带链

太平洋蓝鳍金枪鱼145只切了小口裂并倒角，未做独立带层，却被操作者在SOP中判为通过；这项结论被用户拒绝。静态嘴不是跳过带层/原黑边接续的理由。先确认实际模型节点与最终shader，再恢复真实皮肤/口内公共边、上下带层、完整原画像素簇和实测接头；不能用另画平滑线或借一小块皮肤作完成证明。

原生拓扑且完整曲面已可接受时，`prepare_source_lips.py`可从显式冻结的`native_surface`候选提取公共边，`build_native_source_lips.py`按本鱼原画宽度沿实际体表行走；无需重放黑鲷专用的体素重布面。之后仍走135连续图、140有限三角接触修复与真实蒙皮/冷加载。源图像素坐标与几何投影不是当然相等；切缝偏离原画时先修正确的折返/开口，不让唇图掩盖双嘴。金枪鱼原图口角后的下折弧线不能简成直斜线，也不能为了改口角而挪动整块头宽。

金枪鱼146试验中，旧切缝末端插值实际继续线性外推，错误地钳制终点会把下唇判成上唇并产生中央突柱；该候选作废。向前挪口角又改变了已冻结头宽，亦作废。当前本鱼参数保存在`resources/volume-fish/pacific-bluefin-tuna-repair-146.json`；保持X/Z与原头宽，并保护原图完整眼区。几何改变后旧077/177/490与材质参考报告不再作为本候选验收。
