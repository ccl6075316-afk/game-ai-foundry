# 原像素鳍抠图：边界精确，不用分辨率替代

2026-11-01五鱼宽度/切鳍返修。当前结果只读游戏项目 `plans/reviews/five-fish-width-detail-20261031/manifest.json`；操作者通过不等于用户接受，未替换正式安装。罗非鱼作为已认可的切边质量参照，不复制它的鳍形或尺寸。

1. 用户说“不够精细”时，本轮含义是漏鳍像素、余边、白边或邻近身体材质。先看原图上下文、旧RGBA、原尺寸像素网格；保留原RGB，只编辑本鱼各鳍的alpha。加分辨率、重画或沿像素加面都不解决这个问题。
2. 每鳍独立冻结根、自由边、原画ROI和遮挡解释。中位鳍根常为凹曲线，纯凸包会把身体一侧透明支撑当自由鳍；`native_fin_support.py`用独立根曲线裁支撑笼，低面三角承载原alpha。虹鳟胸鳍的暗外沿只能在自己的局部走向内搜索，不能全局删白/删黑。
3. atlas填充要包含支撑笼的完整UV范围和间隔，不能只按alpha包围盒分配，否则透明笼点会读进相邻tile。`prepare_precise_fin_masks.py`冻结标注快照；`refine_precise_fin_cages.py`生成独立作者参考，未验根时不得称完成。
4. 核对每片有限鳍的两面：`validate_precise_fin_preservation.py`分别按UV正负朝向确认全部保留alpha都被覆盖；同时验证原RGB、实际tileRGBA、闭壳/非零面积、受保护嘴眼身体/尾鳍属性和骨架/原动作。双面并集完整不能代替每一面完整；实际上下文/装回身体后的多视仍要看。
5. 厚度与切边同时保留。长斜耳三角可能绕过厚度控制点，局部Lawson翻边可在不加面的情况下改善；胸鳍可按自己的旧自由片拟合中面，保留完整源根带。只按投影轴的厚度不足，仍用实际相对法线射线、旧薄片负例、尾柄完整截面和端/俯灰模检查。
6. 完整根带投到同一姿态的实际身体面；左右配对鳍限制在自己的侧面。根蒙皮可用实际490轨迹拟合非负归一化的最多4个身体影响，UV/静态位置/动作不变。`portable/export_fin_skin_matrices.gd`仅是诊断，不是490验收。拟合后仍独立冷导出并跑正式全鳍门。
7. **实际蒙皮数组会重新编号。** Godot按三角访问顺序重排逻辑部件，长度相同也不能把源三角编号直接套实际坐标。`portable/fin_vertex_identity.py`先证明静止位置一一对应和唯一分离，再验证全部实际三角集合；之后才能诊断有限长弦。相关负例回归覆盖乱序、错误模型和重复点。
8. `subdivide_finite_root_chords.py`只细分实际失败的完整根面长弦，将新点投到实际身体支持面；旧根点全部保留，新点的几何源参数沿原边插值，不能用投影后距离重猜/缩小根区。保持完整总面数预算、鳍厚度和原0.5mm根缝/0.02mm自由面门。每次修改都使旧报告失效。

本轮五鱼（虹鳟/褐鳟/大西洋鲑/海鲈/红皇帝鱼）最终为1860/1896/1956/1958/1746三角，均保留正常原生/四动作，当前源/独立冷导出、嘴开口/旧闭缝负例、头宽正负例、完整490/072/077、实际正俯斜灰模、视频与逐鱼SOP通过；仍高于1500优选，低于2000硬上限。宽度采用本种FishShapes保存标本数据作约束，具体横向曲线仍为D级制作推断，不把颌关节跨度当唇口宽。

失败必须保留原因：虹鳟r16–r19诊断曾把源三角编号用于重排后的实际顶点，增加了无效细分；不能复用。正确映射从r15只选23条边，r22余下一个姿态根缝0.51349mm穿入，r23整个背鳍向背侧0.04mm后在原阈值和原动作范围通过。没有静止埋入根点，曾尝试的“抬埋入层”诊断当场拒绝，未采用。其他鱼小间隙和蒙皮参数均留在本鱼作者报告，不能推广数值。
