## 开工定位与结构选择

1. 从游戏实际入口定位 GLB、身体 `.res`、口内网格、材质、源图与权重，并冻结哈希。GLB 可能只是骨骼和鳍供体，不能用其未被装配的旧身体作验收对象。
2. 在未清洗源图及同种资料上标注上下唇线、后口角、下巴底线、开度和横宽。深色描线不自动等于口腔负空间；原图有实体皮肤的位置必须仍有体积。
3. 默认分支 `integrated_jaw_cut`：沿下唇线切开连续身体，构建有限口腔内壁、上颌、下颌和脸颊过渡。已有真正独立开合颌采用 `anatomical_alternative`，记录物种依据与动作关系。两个分支都不得另挂独立唇带。
4. 保留当前鱼已获认可的吻型、眼前宽度、鳍与动作；仅改本次证据指向的部位。物种坐标、宽度和图集供体不得照搬另一条鱼。

## 固定施工与停点

| 步骤 | 必须留下的结果 | 失败时处理 |
|---|---|---|
| A. 源图标注 | 口线、口角、上下外皮、口内、下巴、眼纹在同一画布标注 | 查原图和同种资料，不凭一条黑线猜切口 |
| B. 灰模 | 正、侧、俯、腹、斜视对照口裂、眼前宽度、上颌和下巴实体 | 先修整体形状，不能用材质藏错误切面 |
| C. 身体切口 | 沿冻结边界裁切并接回上下颌，有限口内壁与正常口腔缺口；口腔以外闭体 | 消除锯齿边、扇形折面和悬空/重叠内层 |
| D. 原画接续 | 上下颌和口内外的实际 UV、原像素块、材质供体与骨骼权重 | 检查图集尺寸、投影顺序及真实接头，禁止画一条统一假线 |
| E. 局部预检 | 灰模、材质、多视、动作、眼与头宽保留、实际资源冷读 | 回到 A—D 的具体失败环节 |
| F. 固化验收 | 可编辑源、最终 GLB 和引擎资源一致；完成身体077、鳍177/490、动作与 SOP 门 | 输入变化后重跑对应报告，不复用旧哈希 |

**E 稳定前不启动最终177/490。** Smooth 笔刷只能处理已接合表面的局部起伏，不能填真实洞；深凹先补体积，再平顺。口角折返按源图和同种资料决定，不将后段深色描线整段挖空。用户要求缩口时同时检查上下口缘投影顺序、后根实体和下巴，不能只压缩包围盒。

## 已退役路线与历史边界

139—147 的 `prepare_source_lips.py`、`build_source_lips.py`、薄带 UV 接头和 `Source_lips139` 只保留为历史证据，不在新鱼或返修鱼上运行。145 金枪鱼的静态口裂/小倒角失败仍有效：它们没有形成真实颌体积；该失败现在由 C 步真实切口和上下颌解决，而非重新加带。旧清单的带层通过不等于新方法通过，不能迁移旧接受记录。

### 梭鲈后口填补失败补充（2026-10-26）

用户明确不要后线、要求填上一部分时，压成亚像素口缝仍不满足；须证明原空腔被实体占据，同步移除该区口腔/唇面与旧线材质。局部atlas不是整张源图坐标域，写donor前先读实际尺寸并测真实采样。本轮真填通过闭体与24个占体积点，正确扩atlas后仍有贴片/灰边，统一灰模也有棱纹；第三轮终末拒绝并停止，不作成功模板。连续几何、法线、附层与材质相位须实际看图，残缝单因未知时保留未知。

### 梭鲈下颌重建试验补充（2026-10-27）

用户进一步授权切除问题下巴并从较高口沿重建。三版隔离试验分别留下旧布面贴片/硬线、单中心径向扇形折面，或纵向放样的斜折；新顶点材质仍紫色。详见 Fish `plans/reviews/zander-jaw-rebuild-20261027/`；三版均拒绝、未安装。第三版揭示按面重心整片删除会留下锯齿保留边，两侧 X 倒退 29/66 处；纵向放样不能补救错误边界。下一方法先做真正有限三角裁切并冻结平顺上沿、两侧脸颊、下巴底线、前端短口和横宽，再按纵向截面放样建立连续体积；它仍须实际完成原像素/带层接续、蒙皮和正式专项门，不能把这条建议写成已验证模板。

### 已接合网格的局部雕刻整平

用户已用雕刻修好主要轮廓时，先冻结该可编辑源；对刷子试验只在副本上做。真正的开口边仍先接成连续网格，Smooth 笔刷只负责已有曲面的细小起伏，不能把真实洞或应保留的口角负空间当表面坑抹平。Blender脚本驱动的 Sculpt Brush Stroke 在无界遮罩下可能影响整个头部；先用柔边遮罩限定额吻/下颌目标域，测量受影响顶点范围，再看同机位侧、正、腹、斜灰模。深凹需少量补高时分开试笔；强 Inflate 容易顶成圆包，看到新鼓包立即拒绝，不靠再加大 Smooth 遮盖。保存前移除临时遮罩，保留 UV、权重和骨骼，再独立导出、冷读及按当前候选运行适用验收门。梭鲈本次轻笔触参数和较强笔触负例在本鱼 review 中，不作为其他鱼的默认半径或力度。

整片整平也可用 Edit Mode 的 Smooth Vertices、Sculpt Mesh Filter Smooth 或 Smooth/Laplacian Smooth 修改器；先用顶点组/遮罩限制范围并保护唇缘，比较当前源和试验灰模。`Shade Smooth` 只改法线显示，不补实体体积。Smooth 通过邻域平均消细纹，深而宽的凹处仍可能保留；加大迭代会移动或缩小下颌，不能用机械位移小于阈值替代看图。梭鲈局部修改器轻档视觉收益小，中强档移动颌侧而未填后口角，已保留试验记录但未采用。

材质预览前检查 `.blend` 内的原图是否真正连到当前身体材质：打包图片存在不等于导出时已有贴图。逐层核对实际 UV，以原尺寸像素最近邻试投影，灰模和材质在同机位看侧/斜/正/腹。只有正确的眼和侧影仍不足以证明下颌UV接续；斜面和腹面重复条纹是拉伸证据。孤立 GLB GPU 预览标为预览，不把其采样或外观自动当作正式 Godot shader 及用户接受。

梭鲈本轮的决策顺序：先保留用户手工雕刻的连续体积；柔边遮罩内用低力度 Smooth 笔刷处理接缝细纹，小力度 Inflate 仅试真正需要补高的浅凹；任何新圆包均撤回。整片 Smooth 修改器从轻到强分档在副本试，必须逐档看同机位灰模，不因数值运行成功就叠加到已接受形体。贴图要同时在孤立 GLB 和游戏真实装配入口看；若游戏用旧 GLB 作骨架/鳍供体，再以保存的身体 `.res` 覆盖，需核对依赖它的眼部支持绑定、缺失唇层、纹理及原有鳍，重新跑身体 GPU 覆盖与完整鳍门。透明区外推色只能修透明缺块，原画自身的黑线被 UV 拉伸时仍须视图判断，不能把换不透明供体写成解决。此次参数和用户外观选择只归梭鲈，不推广为默认。
