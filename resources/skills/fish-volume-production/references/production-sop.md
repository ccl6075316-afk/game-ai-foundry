# 鱼类生产 SOP：准备 → 源图 → 形体 → 材质 → 动作 → 验收

适用：Game AI Foundry 新建、重建、局部返修和批量推广。本文是执行顺序；专题文档保存细节，物种 profile 保存参数，handoff / validation report 保存本次状态。执行前先定位 Foundry 根目录与目标游戏，下面代码路径均相对 Foundry 根目录，不能相对本机安装技能目录解析。

**每次从这里开始，不按历史实验编号逐个试错。** 新鱼走全部阶段；返修先做阶段 0 的影响判定，再从相关阶段进入，交付仍补齐被影响的验收。用户指定已修好的案例时，先恢复最终样板并看成品，列出完整方法链；不能只拿其中一个脚本当完整流程。

## 0. 固定任务、当前基线与回归范围

输入：用户范围、当前 Brief / Production Delta、游戏实际模型清单、源资产账本、当前 handoff、安装文件和最新有效报告。

1. 记录学名、展示体长及 TL/SL/FL 口径、年龄/性别/姿态（未知就写未知）、画风、是否需要开合嘴、使用的游戏/引擎版本。
2. 保存当前实际模型、源图、profile、运行 shader/helper、动作配置和导入数组/LOD 的哈希。实验候选与正式安装位置分开。已有用户偏好的基线不能被未经检查的候选覆盖。
3. 批量任务列出全部当前鱼：需要修复 / 不适用并保留原形 / 待查证；每鱼有具体观察与证据，不能把少数样例说成全批完成。
4. 为已知缺陷保留能复现的旧图或失败报告。记录本次修改会使哪些报告失效：形体/拓扑会影响材质参考、眼/唇附层、蒙皮、鳍接触、身体、动作与LOD；材质变化也会影响身体覆盖、材质归属和运动稳定。

输出：本鱼生产计划、冻结基线、影响清单。不能只写“沿用旧版，所以通过”。

## 1. 每条鱼的材料包

建模前按目标物种填写，不足项注明如何解决，不以其他鱼的比例补空。

| 材料 | 必须回答的问题 | 不能代替什么 |
|---|---|---|
| 同种研究卡 | 学名；阶段/性别；头吻、口位、颌关系、眼位；鳍/须/脂鳍等部件清单；同测位尺寸与来源 | 生成图不是解剖证据；最大体长不是头宽 |
| 真实参考 | 同种侧头、正/俯视吻部、背腹或鳍连接等本次疑点；记录出处、姿态及适用范围 | 不同个体、群体、幼体和近缘种不能拼成同一组实测 |
| 已接受风格参考 | 哪张负责像素簇、描边和明暗；哪张负责目标鱼的主色和特征 | 鲨鱼灰色不能变成彩色鱼的统一配色 |
| 原尺寸侧面源图 | 全鱼、明确朝向、相同口开度、完整轮廓、鳍可区分、原生分辨率及哈希 | display_size 不是导入分辨率 |
| 条件性辅助源图 | 正面/俯面/腹面是否有必要，承担几何参考还是材质供体 | 多一张图不自动解决接缝、厚度或物种真实性 |
| 源图标志点 | 吻端、上下唇、嘴角、下巴、眼、鳃盖、全部鳍基、尾柄；整画布坐标和口开度 | alpha 外轮廓不能直接当真实口裂 |
| 参数与验收计划 | 截面/部位尺寸、几何归属、供体排除区、根带、动作范围、检查限值及理由 | 不能候选失败后放宽容差或缩小选区 |

目标游戏材料入口：`docs/3d-fish/PREPARATION.md`、`ANATOMY-RESEARCH.md`、`MEASUREMENTS.md`、`species/<species>.md`。先将资料转成制作约束，再建模；未见横宽、背腹纹理和动作幅度通常是制作推断，不能写成实测。

## 2. 决定要生成哪些图，并先接受源图

145新物种排错补充：按[新物种生图与源图拆分排错](new-species-source-review.md)审核实际视角、部件数量/比例、独立裁图坐标、身体补纹与鳍根痕迹。生成成功不等于辅助视角正确；失败加密和错误材料归属不能成为新鱼模板。长吻的口裂与吻端、前吻补色的终止范围分别固定。

**基本输入是一张已接受的完整侧面像素鱼图。辅助图按用途增加，不默认每鱼生成四张，也不因侧图存在就默认够用。**

| 图 | 何时需要 | 生成与接受要求 |
|---|---|---|
| 侧面 | 新鱼基本源图；已有已接受源图可复用 | 引用已有像素鱼作风格参考；物种特征、完整鱼鳍/须、眼嘴、姿态、轮廓、配色和像素尺度先审核 |
| 正面/前斜面 | 宽吻、横向特殊头型、复杂上下颌，或侧图无法支撑正面材质 | 先查同种资料；与侧图同个体设计、同口开度、同风格；注明是否用于贴图，不当生物实测 |
| 俯面 | 头顶横向轮廓、双髻头翼、眼前宽度或背部特征不能可靠推断 | 保留该物种头型及左右眼关系；不能只为了纹理方便捏尖 |
| 腹面 | 腹位嘴、腹面色斑、特殊鳍根或底面结构有实际需要 | 与已接受源图匹配；鲨鱼腹位口不能套端位硬骨鱼嘴 |
| 动作参考图/视频 | 需要判断目标物种游法、鳍参与、开合颌，或制作独立动作资产 | 区分生物参考、生成素材、引擎验证录像；生成视频不能证明实际骨骼动作正确 |

没有新源图需求时，复用已有正式来源，不能补造生成或接受记录。辅助源图实际参与建模/材质时也必须通过资产审核并绑定哈希。

先按 toolkit 执行 `workflow context → validate → init → run → status/resume`，均带 `--json`；运行中只查同一 job。源图完成且接受后再 `volume plan → build → validate → render`。已有来源按 `volume replan` 的归档合同复用；缺失历史路径先定位/恢复，不绕过来源门。

输出：已接受源图清单、每图用途、原尺寸/哈希、完整标志点图、profile。此时只代表输入接受，不能代表成鱼接受。

## 3. 先做身体、头和完整颌部灰模

1. 按源图侧影与物种截面构建闭合鱼身；区分裸身体、装饰层和鱼鳍。头长、眼平面、鳃盖宽、躯干宽高、尾柄分别核对，不用全体包围盒代替局部测位。
2. 看额头/眼前 → 吻端 → 上下唇 → 下巴的完整过渡。鱼身纺锤形不意味着嘴应收成针尖；不能保留平切端面再添一个尖突、圆鼻或鸟嘴。
3. 拓扑不够表达曲面就重布面；连续支持域允许填凹、消减突角。保留合理眼前宽度，不能为材质取色缩颅。
4. 独立下颌须给旧下颌体积让位，补真实口内面与口角连接；闭、半开、张口分别校准。近闭合小口与独立颌采用不同结构方法。

阶段图：**同姿态、同口开度、固定整画布和相机**的源图/旧版/候选侧面；灰模正、反侧、俯、腹、斜视；吻部近景。不可独立缩放局部隐藏偏差。

检查：`check_source_contour.py`；物种冻结横向包络时用 `check_head_form.py` 并保留旧尖头负例；按结构选 `audit_oral_jaws.py` / `audit_separate_jaw.py` / `audit_reference_jaw.py`。这些脚本的输入支持域须匹配本鱼，不能给不支持的结构写通过。

输出：灰模审阅、有效轮廓/尺寸报告、未知横向形态说明。灰模未解决切面，不进入用材质掩盖问题的循环。

## 4. 嘴：完整复用已验证方法链

**先执行[嘴部执行卡](mouth-execution.md)**：定位当前实际资源，选择已有实现分支，写清仅本鱼需要适配的参数。A源图标注→B完整灰模/真实口裂→C上下浅凸带→D完整原像素接续→E局部/冷读预检→F冻结后完整验证。E未稳定不启动最终177/490；不按历史编号反复挑候选。具体失败路线和停止盲调规则见执行卡。

146用户拒绝金枪鱼145成品：**静态口裂、小倒角、前吻补色均不能代替上下薄唇带与原画黑边色块接续。** 不得以“近闭口分支”将这项改成已完成。新鱼必须在实际游戏节点/资源中指出唇带、实际原画供体和接头，并展示身体单层、带层与最终图。只有结构确实不同且有依据时才选择别的实现；脚本存在、SOP全勾选或鳍/身体技术门通过，都不证明执行了这条制作链。

**对本次这类“嘴前平切、描边竖成人中”的问题，黑鲷126—135是完整方法样板，不能只做圆化或擦黑线。** 看 [嘴部材质接续](mouth-material-continuity.md)，恢复并对照最终135成品，而不是133/134失败原型。

顺序与完成条件：

1. **完整曲面**：先完成上一阶段的额吻、上/下唇和下巴过渡；131的消减方式用于解决剩余端面，不前添尖。
2. **上下薄唇带**：由真实皮肤/口内公共边和原画唇色带确定形状；按实际曲面距离铺带，延续两侧宽度与收束，贴合体表并保留口缝。不能套整圈厚管。
3. **原材质运输**：保留源UV及原材质参考坐标；换拓扑后按真实顶点顺序重绑身体、眼等查找表。原图坐标、实际身体UV、唇带UV分别测。
4. **错位竖描边归属**：只修确认被投到鼻端的侧图外轮廓足迹，用明确原皮肤块与连续空间归属处理。保护真正唇线、鼻孔、口缝和天然斑纹，不能全局删黑。
5. **用原黑边色块覆盖、接续薄唇带**：沿实际接头延续原画的完整黑边、灰阶和唇色色块；保留块形、大小、跨唇尺度与排列相位。不能另画光滑线，不能从原图抠碎黑点重新排。必要时薄带与邻皮肤共享连续图；下唇采用真实下外边界。
6. **逐层对照**：原图、灰模、身体单层、薄唇层、最终材质以及同尺度接头放大一起看。黑线在正确唇缘才算完成；仅“变圆”“黑像素减少”“供体RGB相同”不算。

140用户逐鱼复评补充：蓝鳃与罗非鱼139上唇标线曾落到嘴缝/下唇区域，上唇必须在未清洗原图上单独确认其皮肤带与嘴缝边界，不能因下唇已对就复制其取样线。新的带应有可见但轻微的浅凸、向皮肤融入，并独立检查顶点、边中点和面内是否被弯曲身体埋住；只保证顶点在外不够。当前逐鱼修订参数以 `resources/volume-fish/fish-revision-140.json` 为入口，139对应失败上唇参数不再推荐。完整原画色块和实际接头仍按135保留，不改为另画统一黑线。

黑鲷参数、源列号、宽度、供体、曲率和接头排号仅属黑鲷。其余鱼复用方法顺序，重新确定本鱼参数。鲨鱼腹位口、已有独立开合颌等不适用同一唇带结构时，先记录结构分支与依据，仍完成嘴部形态、材质和动作审核，不能无说明略过。

实现链与复现：`remesh_head_trial128.py`、`prepare_lip_band129.py` / `build_lip_band129.py`、`transfer_material130.py`、`round_mouth_trial131.py`、`preview_nose_ink132.gd`、`probe_lip_uv135.py` / `build_lip_uv135.py`；最终输入与命令在目标游戏 `docs/3d-fish/MOUTH-STUDY-135.md`。编号脚本有单鱼假设，推广时必须显式参数化并保持对应语义，不能仅改物种名执行。

140范围与接触补充：用户已认可或暂留的下唇，不能因修上唇顺带重建。蓝鳃、草鱼、罗非鱼恢复139下唇几何、材质及相邻身体图集，并证明局部身体支持域未变；这属于保留证明，不得冒称旧下唇通过新的浅凸接触门。梭鲈是明确下颌根修复，须对新下唇的实际有限三角细分后检查边和面内。距离符号按闭合身体判内外；分缝位置按077的1e-7精度归一，仅为分类索引统一绕向，不改实际距离三角。最近面法线点积和混乱面绕向均曾误判，不能作为最终内外依据。完整记录与失败原型边界见目标游戏 `docs/3d-fish/FISH-FEEDBACK-140.md`。

## 5. 眼睛：清理错误归属，再保留/建立实际眼层

浅凸眼按[眼片执行卡](eye-volume.md)操作：148旗鱼已获实际游戏外观接受。先按正常游戏尺寸判断收益，再以当前实际头部制作浅凸眼片，保留原画眼纹与闭合不透明身体；近景查缺陷。不能照搬银龙鱼或旗鱼尺寸，不自动批量替换。历史失败、实际验证与局部用户接受分开记账。

1. 核对原图眼中心、双轴尺度、完整眼圈、正常侧眼和目标物种眼位。已有立体眼应先保留；不能无理由统一变成凸球、大眼或下移。
2. 分清三域：原图完整眼纹、独立眼层、旧补色分支的染色足迹。追踪真正 shader/供体，不把鳃盖、鼻孔、鲑鳟斑点误当重影。
3. 只退役错误重复投射；保留承担嘴/轮廓等其他功能的分支。独立眼层在静止空间定位，跟随真实皮肤蒙皮；需要浅凸眼盖时按真实身体表面插值骨权重。
4. 保留nearest、源像素、原光照与透明融合；巨骨舌鱼装饰叠层的眼重影不等于允许删除整个17档融合层。

阶段图：原眼标注；侧/反侧/前/俯/斜视；眼归属探针；修复域外对照；所有实际LOD和三距离的动作/切换图。

150批量执行补充：先逐鱼盘点实际可见眼网格与正常尺寸收益，保留合适的原生立体眼，逐鱼记录采用理由。读取当前身体及非零alpha可见融合层；保留原始基础层像素，分开处理mipmap缓存。有限支持三角和重心身份、边缘贴合、实际身体/GPU、完整鳍根及四动作/十二方向切换分别验证，详见眼片执行卡。推广授权不等于新外观已获用户接受。

150后续接受：2026-10-25用户整体确认本轮眼睛效果；19条更新、8条保留的逐鱼方法已完成推广验证。新鱼以眼片执行卡和本鱼原图/当前支持面为入口，参数逐种确定，已有合适立体眼不重复叠盖。接受记录绑定最终安装哈希，历史pending报告保留；整批接受不写成逐鱼点评或整鱼验收。

方法入口：[源图表面修复](source-surface-repair.md)，Foundry `docs/anvil/knowledge/2026-10-21-fish-eye-rollout.md`，`resources/runtime/godot/eye-ownership-107/`、`build_eye_relief.py`。旧分支关闭身份检查、探针域外RGBA/alpha保留、非空覆盖及LOD都要验；某条鱼退休坏LOD的历史例外不能复制。

## 6. 身体、背腹及未覆盖满的材质

146供体归属反例：金枪鱼145背图从带点的上半侧身借了材质，腹图又反复复制了漏排的鳃盖下缘黑描边。**“原图像素”“同一背/腹半侧”“不透明且远离轮廓”都不是足够的供体条件。** 按目标面分别冻结二维允许区，原图最高背面无点时不得从侧身斑点区补背；鳃盖线、嘴线和轮廓只在所属部位保留。逐像素供体图须叠回未清洗源图，与实际俯/腹/正视一起审。UV局部正确、RGB来自原图与几何覆盖通过，均不能替代纹样归属检查。

1. 先区分真正几何孔、透明裁切、源侧图外alpha回退、鳍残影、外描边拉丝、眼嘴重复投射和正常斑纹。分别看灰模、无光照、实际材质和隐藏独立鳍后的皮肤。
2. 两侧使用既定源图；背、腹、吻端等新增面用**原图二维安全像素块**延续。背腹供体分别来自对应半侧，排除鳍/眼/嘴/外轮廓污染，保存逐像素原图XY及回退来源。不能拉一行像素、铺纯色或全局删黑。
3. 实体身体各surface走独立不透明管线；正常口腔保留真实几何。活动鳍保留原透明轮廓。装饰透明叠层须证明下面的身体独立完整，不能强制所有层不透明。
4. 材质场使用实际导入静止XYZ/normal/UV；Godot Compatibility已蒙皮的VERTEX不能冒充rest。换拓扑/顶点顺序/LOD后重绑查找表，逐surface独立材质与哈希。
5. 比较正常游戏距离、近景及实际水下效果；没有水体时只可用标注的可读性压力模拟。像素风主色、完整色块和体积层次一起保留。

140补充：制作前先生成原图部位归属图，分别标出全部鳍（含绘画外缘/根影）、鱼身外描边、眼嘴鳃盖等保护特征及可用二维皮肤供体。3D鳍的UV选区可能小于原画鳍纹，须补完整人工足迹并排除邻边。尾柄和腹部残鳍/描边优先处理供体归属；不要为适应贴图缩错已正确的身体。原始源图与真实活动鳍材质保留，派生清洁皮肤只绑定身体。

补纹理可采用原图整块匹配和最小误差接缝（image quilting）；以同高度/同身体区域限制供体，用低频明暗引导选择，最终保留原尺寸像素簇并记录逐像素供体XY。神经网络补全在需要且获授权时可作为候选/引导，仍要比较源画风、纹样尺度、色阶、拼缝及隐藏鳍后的实际身体；“模型能运行”或“每像素来自原图”都不证明自然。方法来源和140实现边界见 [源图表面修复](source-surface-repair.md)。

阶段图：侧/反侧/正/俯/腹/斜视灰模、原色、材质；背腹近景；隐藏成对鳍/眼盖后的实体皮肤；供体和UV归属探针；静止与最大摆动覆盖对照。

工具：`build_surface_charts.py`、`freeze_body_opacity.py`、`validate_body_integrity.py`；`BodyChart112` + `RestSurface114` + `ValidateSurface112`（在 `resources/runtime/godot/surface-chart-112/`）；材质锚定用 `probe_material_anchor114.gd` / `probe_runtime_anchor114.gd`。通用原则见 [源图表面修复](source-surface-repair.md)。

## 7. 全部适用鱼鳍、须和附属部件

**新鱼标准步骤，适用于每条鱼，不是返修补丁选项。** 进入本阶段先读[鳍源图分离与形状](fin-source-shape.md)。材料准备时即独立分离原图的整片鳍，保存原尺寸RGBA、alpha/原像素坐标、自由边及完整基线；并分别标出活动鳍、身体上的鳍基连接纹理、待清理的旧鳍残影。新鱼从这些独立源图建立鳍和UV，再装回身体，不能建完后只跑连接门。

完整轮廓、二维原像素覆盖、装回身体后的可见面积、鳍根连接、自由面穿体五项独立验，不能用177/490通过宣称形状相同。旧profile/UV不是真值。单侧收折画不能自动当真实展开材质，必要的独立展开参考/辅助图也须准备和接受。罗非鱼141—142是经用户认可的方法样板；复用顺序和验证义务，每鱼重新确定轮廓、基线、身体保护域、宽度与展开参数。

标准交付必须保存：①每片原生鳍与身体归属清单；②原图/切片/实际UV及同画布模型轮廓对照；③独立鳍、装回身体的完整/遮挡图与可见面积说明；④隐藏鳍后的身体连接纹理；⑤新候选177/490、身体/GPU、原生循环、四动作切换与录像。`volume sop-init/check`已将源分离、形状对照、遮挡证据和身体鳍基保留列为必需项。旧记录不追造历史验收，重新检查时按当前标准补足。

143推广补充：先完成独立源图切片、静止实际GPU/穿体、材质冷加载及隐藏鳍后的原色回归，再冻结最终候选跑昂贵177/490。侧面局部含有鱼身时，先切片复核，不能把整个ROI都当成缺失鳍；银龙鱼背鳍、蓝鳃臀鳍的初筛印象即由独立切片纠正为保留。只复用罗非鱼方法与检查义务，每种鱼独立选自由边、完整基线、原生像素到实际引擎单位及实际展示缩放。

身体连接纹理的归属还要检查真实材质坐标：旧头嘴可能借用鳍根附近的源像素，UV遮罩不等于身体部位。出现重用时，用已绑定的不可变rest坐标限制连接区，不用动画后的VERTEX；身体、眼嘴、活动鳍分开看。用无光照图判断原色归属，正常光照图判断外观；明暗变化不能自动当作UV泄漏。给同一新着色流程提供零遮罩对照，区分本次补色与着色流程本身的最近采样边界差异，保留实际差异数量/位置，不冒称整幅RGBA逐像素不变。

保存材质时，全部surface的Shader和原生纹理都须可独立冷读；`FLAG_BUNDLE_RESOURCES`和同一进程先加载旧材质再读新材质，均不能代替新进程检查。原GLB材质冻结成便携资源时，将运行时shader代码及每个纹理的原尺寸Image显式内嵌，复验原字段、LOD索引/距离、RGBA和GPU。不透明身体与活动鳍alpha仍独立验证；不能因鳍资源通过就忽略身体或口内其他surface丢贴图。

旧鱼改造先分级，不全批换鳍。原图可确认的主轮廓被截成错误形状、完整鳍片明显缺失/被身体吞掉、相邻身体混入活动鳍等列为严重；源可见域缺失约15%或长度/展开跨度差约20%可触发人工复核，但不是自动解剖真值。轻微差异保留，边界不明先查证。每个处理决定须有原图和实际网格证据、严重程度及理由；仅旧profile面积分数不能触发修复。

1. 按物种清单逐个建立背/脂/臀/尾/左右胸/左右腹等部件；非适用项有依据。源图冻结完整鳍基折线，不以单锚点代替；须记录左右数量与根点。
2. 鳍根贴实际同姿态身体面，根带继承局部身体权重、远端渐变回鳍骨。长基线细分；尾基可限定后端面，背/腹基线选择正确解剖面，不能统一最近点向内压。
3. 保留鳍自由面、鳍条、外缘描边和alpha；活动鳍展开后身体不能还画着同一片鳍。分别保留身体上的鳍基连接纹理：独立鳍切片排出的身体像素，不应一并从鱼身清掉。原画/隐藏鳍/活动鳍展开三视对照，确认连接标记留在身体，旧鳍残影被补皮肤；142罗非鱼圆弧案例见专题。
4. 根带连接与整片自由面穿体分开验；完整根带/边插值、两面顶点、边及三角内部均覆盖。不缩选区、不锁鳍、不降低动作上限来掩盖失败。

阶段图：灰模/材质五视；全部根区标注；成对鳍展开及背腹视；静止、原生循环、四动作、切换、最大幅度。

工具：`freeze_authored_fin_roots.py` → `validate_fin_completion.py`（177姿态）→ `validate_fin_membrane_clearance.py`（490姿态，包含原生循环）。导出器必须对应游戏真正使用的物种控制器；112及之后专用控制器采用 `export_runtime_fin_roots112.gd` 或明确等价的新候选导出器。`model unchanged` 不能代替实际接触门。

## 8. 骨骼、动作与衔接

材料：同种游动方式资料、鳍参与和形态约束、原生循环、实际游戏控制器/骨名/动作配置、需要的开合颌参考。动作幅度/频率是制作参数，未知生物上限单列。

1. 先做安全静止姿态、骨支点、归一权重与正确局部旋转轴；更换网格保留或明确运输蒙皮，不以静态预览冒充可动成品。
2. 原生循环检查完整相位与首尾；实际运行 Swim / Turn / Ascend / Dive，分别检查身体与鱼鳍独立幅度/频率，零幅度、最大幅度、中间值与参数变化。
3. 转弯分开处理头部轨迹、整体朝向与身体传播，不绕身体中心硬转。逐一看切入、动作中、切出和真实切换，不能只测四段各自播放。
4. 开合颌另验闭/半开/张口和嘴角/后根连接。新行为如滑行、停顿、靠近观察是额外范围，不能用标准四动作报告冒充已经覆盖。
5. 需要续做2D/生成动作时，从已接受动画的稳定动态帧取参考；首尾分别匹配切入/回接动作。只有运行时使用镜像，尾帧才可按目标游动帧镜像。生成帧流程见 `docs/FISH-TURN-WORKFLOW.md`，不替代3D引擎测试。

证据：原生循环采样、四动作与真实切换图/报告、含极端参数的完整鱼体和局部近景、至少20秒整体环绕和动作录像。模型本身在游戏里运动；生成视频不是测试录像。

工具：`volume motion-plan/build/validate` 管冻结动作输入；`validate_motion_and_surfaces.py` 管实际控制/材质；鳍177/490门、身体覆盖、材质锚定/LOD门共同复验。离散采样不宣称全连续时间无碰撞。

## 9. 最终验收材料包与顺序

先冻结最终候选及运行依赖，再收集下列证据。任何受影响文件变化，相关旧报告失效。

| 验收层 | 必须拿什么比较 | 通过条件 |
|---|---|---|
| 来源/物种 | 已接受源资产清单、真实资料、同测位参数表、未知项 | 来源真实；物种/姿态/口开度相符；推断不冒充实测 |
| 局部形态 | 固定画布的原图/旧版/候选；灰模正侧俯腹斜；嘴、眼、鳍根近景 | 无已指出切面/尖突；口眼与物种约束一致；有限三角无翻面/裂缝 |
| 局部材质 | 未清洗原图、无光照、实际材质、层隔离、供体与接头同尺度放大 | 薄唇带覆盖及原黑块接续正确；眼无错误重复；背腹无污染、缺块、拉丝 |
| 连接/完整性 | 最终候选完整鳍根/全鳍面报告、逐surface不透明供体、实际GPU同姿态覆盖 | 根/膜面门全部通过，非空且无漏部件；身体除正常口腔外无缺块 |
| 动作/LOD | 原生循环、四动作、真实切换、参数范围、全部实际LOD/三距离 | 无悬空/穿体、口眼层错位、贴图滑转；零幅度/独立控制正确 |
| 整体展示 | 源图/风格参考/成鱼并排，正常与近景，整体环绕/动作录像，实际游戏场景 | 主色、像素簇、比例、遮挡、动态和水下可读性可接受 |
| 可交付性 | 最终文件清单、安装前后哈希、冷启动/导入日志、重放入口 | 装的就是验证过的候选；无未知shader、丢贴图、过期表或错误日志 |

不能互相替代：闭合网格≠无透明洞；源RGB一致≠接头自然；鳍根通过≠鳍面不穿体；静态通过≠动作通过；`profile approved`≠成品接受；提交过≠用户验收通过。

按本SOP的证据清单记录实际观察及文件哈希；汇总检查只防漏项/陈旧证据，不替人看图或替代专项检查器。所有必需项完成后才 `volume accept --handoff ... --note <实际审核说明> --json`；该命令记录操作者审核，不代表用户本人已接受。存在失败/未知的验证能力时明确保留，不能靠注释、复制旧报告或单纯改状态通过。

### 逐鱼证据清单命令

```powershell
.\gamefactory.cmd volume sop-init --species <species_id> --output <本鱼目录>/production-review.json --json
.\gamefactory.cmd volume sop-check --review <本鱼目录>/production-review.json --output <本鱼目录>/sop.validation.json --json
```

首次建清单，之后在原清单补充实际证据；`sop-init` 不覆盖旧文件。清单固定九组必需项：准备、头、嘴、眼、身体材质、鳍、动作、运行时、整体展示。初始化全部为 `pending`，不得一次性填写为通过。返修也须记录各项实际状态，不能把未检查写成不适用。

- `candidate_files`：`source_image`、`model`、`species_profile`、`runtime_manifest`、`motion_config` 的路径和SHA256。另列实际参与运行的脚本、shader、附层网格、材质表、辅助源图和LOD等依赖；模型角色可指候选主网格，原GLB与唇带等组成件另列。相对路径以清单所在目录解析。
- `evidence`：每项以唯一ID保存 `path`、`sha256`、`kind`（`data/image/report/video`）、`bound_inputs`（全部candidate角色到哈希的映射）、`observation`（实际观察与适用范围）。同一对照图可服务多个明确判据，不能用无关图片凑数。
- `stages.<阶段>`：`result`、`method`、`reviewer`、`observations` 和 `checks`。生成的每个判据列表填对应证据ID。确实无开合颌、特殊口型不用常规唇带等，仍须提供本物种分支依据及相应图；不删除判据来绕过审阅。
- `stages.mouth.implementation`：按[嘴部执行卡](mouth-execution.md)填写实际上下带的资源角色、几何导出角色、part与node；或有物种依据的结构分支。仅图片与完成勾选不能代替实际带层清单。检查器拒绝缺失、空/坍缩导出、同一片冒充两唇及陈旧文件；实际运行对应和视觉质量仍单独验证。
- 专项 `report` 必须是JSON，顶层 `ok=true`；操作者仍须核对其物种、输入、样本覆盖和阈值。检查器只验证该状态与文件绑定，不会验证任意JSON中的实验结论。

例如 `mouth.checks.native_pixel_cover_and_actual_uv_joins` 引用实际查看过的原图/薄带/最终接头对照图，观察说明应写清上、下唇的块形与相位、真唇缘及错位鼻端描边是否解决；不能只写“图片存在”。

该检查保守地要求每项证据绑定完整当前候选。文件变化后，受影响项重新运行；不受影响的证据须审查依赖关系、在阶段观察中说明保留理由后才重新绑定，禁止批量改哈希伪造重验。图片能解码、视频非空及扩展名正确仅是文件检查，内容、时长、机位和动作仍须实际看。

`ok=false / next_action=fix_input` 时补材料或返修；报告保留逐阶段和逐判据缺项。`ok=true / next_action=human_review` 只说明证据账本检查通过。此命令是SOP额外检查，现有 `volume accept` 并未自动调用它；执行者必须先运行并检查报告，再完成实际视觉审核和原有接受合同。

## 10. 每次修复怎样回写流程

144侧影交付补充：按[侧面投影与材料包排错](side-projection-review.md)制作当前实际游戏的原图/正交侧影/无光照对照。保留源像素映射、同姿态与共同画布；原图留白不足时共同扩边，不独立拟合模型。总览只等比缩放，不压扁排版。GPU截图必须用实际渲染后端，拒绝无图、日志错误或旧报告；浏览器检查实际图片加载与逐鱼切换。此对照是每条新鱼的标准验收材料，不代替177/490、077或真实多视动作门。

每次修复结束同时更新三层，不能只留一个实验目录：

139推广补充：材质重绑定后，先在隔离游戏目录运行实际物种控制器检查（包括所有口内surface、正面投影及可见性），再批量录制。保存了参考表、静帧正常和文件导出成功，都不能代替这一小步。跨目录使用的材质还须把全部native纹理封装并冷加载；见[嘴部接续139实现约束](mouth-material-continuity.md)。替换式运行资源以新网格及实际骨名/UNORM16权重、当前GPU为身体证据，原GLB只证明保留部件的来源。

139交付补充：恢复旧源图可提取原GLB内PNG字节并与历史接受handoff的SHA核对，不重新编码后冒称原文件。昂贵的490全鳍面检查若按时间分片执行，仍使用相同原检查核、全部鳍及冻结容差；聚合须校验同一输入哈希、完整姿态集合且无缺片。局部交付通过与整鱼SOP分开：本轮发现的范围外旧观察可以保留pending并交给用户判断，不能为了账本全绿而补写通过或擅自扩大返修。

1. **通用方法**：本SOP对应阶段、详细技能参考及通用工具。写清触发条件、完整依赖顺序、输出和验证；新方法与旧方法的替代关系明确。
2. **物种参数**：`resources/volume-fish/` 的本鱼 profile、源图标注、供体/根带/动作范围及依据。不能把黑鲷列号、太阳鱼幅度、某鱼LOD退休例外变成全鱼默认。
3. **本次证据**：handoff、validation、视觉判断、用户反馈、失败反例和可重放输入。知识允许沿用；通过状态必须绑定当前文件，不能沿用。

新建从阶段0顺序执行；修嘴回阶段3/4并使相关5—9证据失效；修眼回5并复验6/8/9；修背腹材质回6并复验身体/锚定/动作/LOD；修鳍回7并复验8/9；改动作回8并复验全部动态连接/身体/材料。根据实际影响保留未变化且哈希一致的证据，不能为局部修改重生所有资产。

仓库技能是维护源。本机安装副本更新后要逐文件比对，确认新入口和引用同时存在；不能只更新仓库而让下次加载旧技能。提交是保存代码/证据，是否验收按报告和用户反馈判断。

每轮验证即收尾：成功的稠密采样、重复帧和临时导入工程及时清理。先按报告引用保留不可替代的基线资源、支持面、原始像素及冻结参数，再归档紧凑报告、失败原因和代表性多视证据；不得只保留通过JSON却删掉它依赖的唯一资源。重建输入与可再生缓存必须在清理清单中区分。
