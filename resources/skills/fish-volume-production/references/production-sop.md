# 鱼类生产 SOP：准备 → 源图 → 形体 → 材质 → 动作 → 验收

适用：Game AI Foundry 新建、重建、局部返修和批量推广。本文是执行顺序；专题文档保存细节，物种 profile 保存参数，handoff / validation report 保存本次状态。执行前先定位 Foundry 根目录与目标游戏，下面代码路径均相对 Foundry 根目录，不能相对本机安装技能目录解析。

**每次从这里开始，不按历史实验编号逐个试错。** 新鱼走全部阶段；返修先做阶段 0 的影响判定，再从相关阶段进入，交付仍补齐被影响的验收。用户指定已修好的案例时，先恢复最终样板并看成品，列出完整方法链；不能只拿其中一个脚本当完整流程。

**实验结束由执行者主动固化并交付，不等待用户提醒导出。** 每次准备完成本轮/正式交付，按[正式资产导出收尾](final-asset-export.md)将静态几何、UV、权重及纹理修正回写可编辑源并导出，保存引擎专用资源；在冻结最终验收候选前完成。新进程关闭实验静态构建链直接冷读导出成品，复核源图/实验版/导出版及实际动作，再运行最终门。进程内缓存、导出成功、实验截图均不能替代。未固化保持实验候选；正常实时动画/环境效果保留。

## 0. 固定任务、当前基线与回归范围

输入：用户范围、当前 Brief / Production Delta、游戏实际模型清单、源资产账本、当前 handoff、安装文件和最新有效报告。

1. 记录学名、展示体长及 TL/SL/FL 口径、年龄/性别/姿态（未知就写未知）、画风、是否需要开合嘴、使用的游戏/引擎版本。
2. 保存当前实际模型、源图、profile、运行 shader/helper、动作配置和导入数组/LOD 的哈希。实验候选与正式安装位置分开。已有用户偏好的基线不能被未经检查的候选覆盖。
3. 批量任务列出全部当前鱼：需要修复 / 不适用并保留原形 / 待查证；每鱼有具体观察与证据，不能把少数样例说成全批完成。
4. 为已知缺陷保留能复现的旧图或失败报告。记录本次修改会使哪些报告失效：形体/拓扑会影响材质参考、眼/唇附层、蒙皮、鳍接触、身体、动作与LOD；材质变化也会影响身体覆盖、材质归属和运动稳定。

输出：本鱼生产计划、冻结基线、影响清单。不能只写“沿用旧版，所以通过”。

### 0.1 按批次修复和验证（151后用户确认的执行规则）

**整体检查一轮 → 汇总本轮问题 → 逐项修复与局部验证 → 本轮整体复看并冻结 → 集中完整验收。** 完整验收又发现问题时，先收齐这一轮检查所能发现的问题，再开始下一批；不在每发现或修好一个问题后重跑整套。新鱼先按阶段1—8建立可检查候选，返修先检查当前基线；这里规定验证调度，不取消来源门、工具输入校验或最终交付门。

#### 一轮怎样执行

1. **集中发现。** 按头、嘴、眼、背腹材质、全部鳍、动作和实际导入整体巡检，使用固定源画布、灰模/无光照/贴图和代表性动作，汇总已确认问题、证据、影响依赖及局部复验方法。主观疑点、范围外问题或无法判断的解剖项分别保留待核，不擅自当作必须修复。问题与结论写入已有Production Delta、handoff或validation report，不另建状态副本。
2. **逐项修复。** 每项只跑能判定该问题和直接回归风险的局部检查。先做快的结构/来源/实际冷加载检查，必要时使用能复现问题的姿态及零/大幅等代表性姿态。若必须跑完整专项才能判断这一项，可以执行该专项，但不顺带把所有其他专项也重跑。一个局部检查通过后继续处理本轮其他问题，不立即进入177/490、整鱼GPU采集、录像和打包的完整组合。
3. **保留与失效。** 对每次修改记录哪些局部结果仍适用、哪些已失效、理由和实际输入哈希。未受影响的结果在制作阶段暂存；受影响项安排到本轮相关局部复验或最终验收。局部通过仅表示这项问题在该覆盖范围内解决，不把整鱼改为完成。
4. **合并复看与冻结。** 本轮待修项均已局部通过，待核项已查明或按用户授权明确处理范围后，将所有修改合并到同一候选做一轮实际多视/源图/代表性动作复看，检查相互影响。没有已知未解决阻断问题，才冻结源图、身体/附层/鳍、材质与供体、骨骼/动作、实际导入数组/LOD及有效运行依赖。自动LOD、nearest、贴图尺寸、导入缓存和冷加载必须在昂贵完整门前确认。
5. **集中完整验收。** 对冻结候选执行第9节适用的最终完整门和实际视觉审核。独立专项可并行，均须绑定同一候选；运行中不继续修改该候选。已有缺陷证据先保留；若无效输入、导入或shader错误使整轮检查失去意义，则停止依赖该失败项的后续检查，先修输入，不为“收齐问题”继续产生无效结果。完整检查后的新问题汇总为下一批，修完一批再整体验收，不逐缺陷重复整套。

#### 局部结果何时可以暂不重验

必须能证明相关输入、支持面、运行分支和检查范围未变。判断依赖，不能只按“改的是哪个部位”或GLB文件名判断。

| 本次变化 | 制作阶段优先复验 | 可以暂存的局部结果及条件 |
|---|---|---|
| 嘴部切口、上下颌与局部身体 | 当前颌部多视、切口/口腔/下巴连续性、UV接头、眼支持与最近鳍的影响 | 后身/尾鳍等须证明实际几何、骨骼、权重、导入与控制未变；不能因为距离远就假定无影响 |
| 独立眼片参数 | 原眼像素与归属、当前支持面、有限三角接触、左右/俯视和代表性动作 | 嘴及鳍局部结果可保留，前提是身体/材质/实际绑定和导入未受改变 |
| 纯颜色或供体修改 | 实际供体归属、多视无光照/贴图、透明覆盖、材质锚定与动作稳定 | 物理局部结果须证明几何/拓扑/蒙皮/导入完全未变；shader若改变顶点位置、alpha、可见性或运行绑定，不属于纯颜色修改 |
| 单个鳍的形状、根带或姿态 | 本鳍完整源形、全根/自由面、身体遮挡、能复现问题及代表性动作 | 其他鳍仅在其几何、身体支持面和骨骼/动作分支未变时暂存 |
| 身体曲面、拓扑、骨骼、权重、动作或展示尺度 | 所有受影响附层、根带/鳍面、身体及动态覆盖；尺度影响绝对距离标定 | 不能沿用受影响结果；先定位局部最小反例，修稳后集中执行最终动态门 |
| 自动LOD、重导出或导入数组/顶点顺序 | 实际导入指纹、静止坐标表、附层支持/绑定及原图形状 | 旧实际数组/LOD报告失效；原GLB哈希不变也不证明可复用 |
| 仅审阅相机、说明或排版 | 实际取景、可读性和对应图片/视频加载 | 鱼的实际几何/材质/控制及导入不变时，物理专项不因纯展示修改重跑 |

最终交付仍按当前合同检查全部适用鳍的完整鳍根/全鳍面、身体闭合与GPU覆盖、动作/切换、材质/锚定及实际LOD；不能把“局部暂存”当作省略最终门。最终材料变更也按原072要求验完整鳍根，不只验本轮改过的鳍。保留证据时保留原报告和原覆盖说明；对当前候选的适用性另记依赖保留证明。`sop-check`要求完整候选绑定，未受影响证据须审核保留依据后才能在新账本引用；不得改写旧报告输入、批量换哈希、降低容差或将历史通过冒充重新运行。

#### 151鲸鲨反例与停止条件

本轮先跑昂贵导出再发现自动LOD、完整检查后又修改头部材质并重跑物理专项，属于候选未定稳的执行返工。后续先通过局部与本轮整体复看，避免已知问题未收齐就冻结；冻后若仍有改动，先判断影响，收集为下一批。没有新变化、新失败或尚未解决的疑点，不为“再放心一次”重复已有效通过的检查。不得借这一规则无限扩大修复范围或绕过用户保留某些外观的决定。

152并行工作区补充：广泛扫描工程文件的验证器可能被不参与本鱼的同时改动中止。先证明冻结的本鱼依赖未变，保留失败报告；必要时在不可变鱼副本中仅续跑受干扰的检查，并证明实际安装资源、shader、配置、控制/尺度/导入与副本一致，说明省去其他鱼/场景的范围。不能删掉验证器的依赖守卫、改失败为通过或重跑已成功的整套检查。

1. 冻结旧实际装配入口和旧 GLB、脚本、材质、纹理、骨架/动作的哈希，记录原有鳍问题。只合并已在旧入口实际显示的静态结果；不能顺手修其他部位或把旧问题标为新问题。
2. 将静态几何、UV、蒙皮和应属模型的纹理回写可编辑源与 GLB。按[导出收尾](final-asset-export.md)从新进程关闭旧静态构建链冷读新入口，核对部件数量/位置、静止网格与UV/权重、材质实际绑定、骨架/动作以及实际导入数组。顶点重排时按位置、UV、权重和有向三角面对照旧实际装配结果，不要求数组次序或文件哈希相同。
3. 用相同镜头/尺度对照旧实际装配与新导出的静止、多视画面；新导出实际拍摄原生游动、转身、上浮、下潜和切换的代表姿态。若能证明骨架、动画数据、控制器与动作参数未变，不要求旧版重复拍全套四动作；任一动作依赖改变时才补同姿态双边对照。实际动作状态必须由控制器快照及不同画面验证；若 `set_action()` 仅排队，随后调用会清待切换状态的 `seek()`，则必须先执行 `step()` 后再检查快照，不能把“动作可选”当成“动作已执行”。仅检查迁移没有引入可见新缺件、错材质、明显鳍脱离或新增穿体；有差异就定位并复验受影响局部。代表姿态不证明全连续时间的鳍安全。
4. 在既有 handoff 或 validation report 写明 `scope=local_godot_static_merge`、新旧输入哈希、冷读与对照证据、已知缺陷、实际差异、局部结论，以及 `formal_acceptance=false`。因重导出失效的旧鳍报告标为待复验；完整根区/自由鳍面177/490、源图鳍形、逐鱼历史空项和其他最终门列为 deferred，不伪填通过。未完成1—3项或发现新增问题时，本地检查点也不通过。
5. 两次计划中的鳍大修完成并冻结正式候选时，按第0.1节集中执行受影响专项和第9节完整验收，再运行 `volume sop-check`。当前 `sop-check` 仍只判正式交付，不用其失败项驱动本地迁移阶段的历史补账返工。

阶段图：原眼标注；侧/反侧/前/俯/斜视；眼归属探针；修复域外对照；所有实际LOD和三距离的动作/切换图。

## 6. 身体、背腹及未覆盖满的材质

146供体归属反例：金枪鱼145背图从带点的上半侧身借了材质，腹图又反复复制了漏排的鳃盖下缘黑描边。**“原图像素”“同一背/腹半侧”“不透明且远离轮廓”都不是足够的供体条件。** 按目标面分别冻结二维允许区，原图最高背面无点时不得从侧身斑点区补背；鳃盖线、嘴线和轮廓只在所属部位保留。逐像素供体图须叠回未清洗源图，与实际俯/腹/正视一起审。UV局部正确、RGB来自原图与几何覆盖通过，均不能替代纹样归属检查。

1. 先区分真正几何孔、透明裁切、源侧图外alpha回退、鳍残影、外描边拉丝、眼嘴重复投射和正常斑纹。分别看灰模、无光照、实际材质和隐藏独立鳍后的皮肤。
2. 两侧使用既定源图；背、腹、吻端等新增面用**原图二维安全像素块**延续。背腹供体分别来自对应半侧，排除鳍/眼/嘴/外轮廓污染，保存逐像素原图XY及回退来源。不能拉一行像素、铺纯色或全局删黑。
3. 实体身体各surface走独立不透明管线；正常口腔保留真实几何。活动鳍保留原透明轮廓。装饰透明叠层须证明下面的身体独立完整，不能强制所有层不透明。
4. 材质场使用实际导入静止XYZ/normal/UV；Godot Compatibility已蒙皮的VERTEX不能冒充rest。换拓扑/顶点顺序/LOD后重绑查找表，逐surface独立材质与哈希。
5. 比较正常游戏距离、近景及实际水下效果；没有水体时只可用标注的可读性压力模拟。像素风主色、完整色块和体积层次一起保留。

140补充：制作前先生成原图部位归属图，分别标出全部鳍（含绘画外缘/根影）、鱼身外描边、眼嘴鳃盖等保护特征及可用二维皮肤供体。3D鳍的UV选区可能小于原画鳍纹，须补完整人工足迹并排除邻边。尾柄和腹部残鳍/描边优先处理供体归属；不要为适应贴图缩错已正确的身体。原始源图与真实活动鳍材质保留，派生清洁皮肤只绑定身体。

补纹理可采用原图整块匹配和最小误差接缝（image quilting）；以同高度/同身体区域限制供体，用低频明暗引导选择，最终保留原尺寸像素簇并记录逐像素供体XY。神经网络补全在需要且获授权时可作为候选/引导，仍要比较源画风、纹样尺度、色阶、拼缝及隐藏鳍后的实际身体；“模型能运行”或“每像素来自原图”都不证明自然。方法来源和140实现边界见 [源图表面修复](source-surface-repair.md)。

阶段图：侧/反侧/正/俯/腹/斜视灰模、原色、材质；背腹近景；隐藏成对鳍/眼盖后的实体皮肤；供体和UV归属探针；静止与最大摆动覆盖对照。

工具：`build_surface_charts.py`、`freeze_body_opacity.py`、`validate_body_integrity.py`；`BodyChart112` + `RestSurface114` + `ValidateSurface112`（在 `resources/runtime/godot/surface-chart-112/`）；材质锚定用 `probe_material_anchor114.gd` / `probe_runtime_anchor114.gd`。通用原则见 [源图表面修复](source-surface-repair.md)。

## 7. 全部适用鱼鳍、须和附属部件

**新鱼标准步骤，适用于每条鱼，不是返修补丁选项。** 进入本阶段先读[鳍源图分离与形状](fin-source-shape.md)。材料准备时即独立分离原图的整片鳍，保存原尺寸RGBA、alpha/原像素坐标、自由边及完整基线；并分别标出活动鳍、身体上的鳍基连接纹理、待清理的旧鳍残影。新鱼从这些独立源图建立鳍和UV，再装回身体，不能建完后只跑连接门。

完整轮廓、二维原像素覆盖、装回身体后的可见面积、鳍根连接、自由面穿体五项独立验，不能用177/490通过宣称形状相同。旧profile/UV不是真值。单侧收折画不能自动当真实展开材质，必要的独立展开参考/辅助图也须准备和接受。罗非鱼141—142是经用户认可的方法样板；复用顺序和验证义务，每鱼重新确定轮廓、基线、身体保护域、宽度与展开参数。

标准交付必须保存：①每片原生鳍与身体归属清单；②原图/切片/实际UV及同画布模型轮廓对照；③独立鳍、装回身体的完整/遮挡图与可见面积说明；④隐藏鳍后的身体连接纹理；⑤新候选177/490、身体/GPU、原生循环、四动作切换与录像。`volume sop-init/check`已将源分离、形状对照、遮挡证据和身体鳍基保留列为必需项。旧记录不追造历史验收，重新检查时按当前标准补足。

143推广补充：先完成独立源图切片、静止实际GPU/穿体、材质冷加载及隐藏鳍后的原色回归，再冻结最终候选跑昂贵177/490。侧面局部含有鱼身时，先切片复核，不能把整个ROI都当成缺失鳍；银龙鱼背鳍、蓝鳃臀鳍的初筛印象即由独立切片纠正为保留。只复用罗非鱼方法与检查义务，每种鱼独立选自由边、完整基线、原生像素到实际引擎单位及实际展示缩放。

身体连接纹理的归属还要检查真实材质坐标：旧头嘴可能借用鳍根附近的源像素，UV遮罩不等于身体部位。出现重用时，用已绑定的不可变rest坐标限制连接区，不用动画后的VERTEX；身体、眼嘴、活动鳍分开看。用无光照图判断原色归属，正常光照图判断外观；明暗变化不能自动当作UV泄漏。给同一新着色流程提供零遮罩对照，区分本次补色与着色流程本身的最近采样边界差异，保留实际差异数量/位置，不冒称整幅RGBA逐像素不变。

保存材质时，全部surface的Shader和原生纹理都须可独立冷读；`FLAG_BUNDLE_RESOURCES`和同一进程先加载旧材质再读新材质，均不能代替新进程检查。原GLB材质冻结成便携资源时，将运行时shader代码及每个纹理的原尺寸Image显式内嵌，复验原字段、LOD索引/距离、RGBA和GPU。不透明身体与活动鳍alpha仍独立验证；不能因鳍资源通过就忽略身体或口内其他surface丢贴图。

旧鱼改造先分级，不全批换鳍。原图可确认的主轮廓被截成错误形状、完整鳍片明显缺失/被身体吞掉、相邻身体混入活动鳍等列为严重；源可见域缺失约15%或长度/展开跨度差约20%可触发人工复核，但不是自动解剖真值。轻微差异保留，边界不明先查证。每个处理决定须有原图和实际网格证据、严重程度及理由；仅旧profile面积分数不能触发修复。

1. 按物种清单逐个建立背/脂/臀/尾/左右胸/左右腹等部件；非适用项有依据。源图冻结完整鳍基折线，不以单锚点代替；须记录左右数量与根点。
2. 鳍根贴实际同姿态身体面，根带继承局部身体权重、远端渐变回鳍骨。长基线细分；尾基可限定后端面，背/腹基线选择正确解剖面，不能统一最近点向内压。
3. 保留鳍自由面、鳍条、外缘描边和alpha；活动鳍展开后身体不能还画着同一片鳍。分别保留身体上的鳍基连接纹理：独立鳍切片排出的身体像素，不应一并从鱼身清掉。原画/隐藏鳍/活动鳍展开三视对照，确认连接标记留在身体，旧鳍残影被补皮肤；142罗非鱼圆弧案例见专题。
4. 根带连接与整片自由面穿体分开验；完整根带/边插值、两面顶点、边及三角内部均覆盖。不缩选区、不锁鳍、不降低动作上限来掩盖失败。

阶段图：灰模/材质五视；全部根区标注；成对鳍展开及背腹视；静止、原生循环、四动作、切换、最大幅度。

工具：`freeze_authored_fin_roots.py` → `validate_fin_completion.py`（177姿态）→ `validate_fin_membrane_clearance.py`（490姿态，包含原生循环）。导出器必须对应游戏真正使用的物种控制器；112及之后专用控制器采用 `export_runtime_fin_roots112.gd` 或明确等价的新候选导出器。`model unchanged` 不能代替实际接触门。

## 8. 骨骼、动作与衔接

材料：同种游动方式资料、鳍参与和形态约束、原生循环、实际游戏控制器/骨名/动作配置、需要的开合颌参考。动作幅度/频率是制作参数，未知生物上限单列。

1. 先做安全静止姿态、骨支点、归一权重与正确局部旋转轴；更换网格保留或明确运输蒙皮，不以静态预览冒充可动成品。
2. 原生循环检查完整相位与首尾；实际运行 Swim / Turn / Ascend / Dive，分别检查身体与鱼鳍独立幅度/频率，零幅度、最大幅度、中间值与参数变化。
3. 转弯分开处理头部轨迹、整体朝向与身体传播，不绕身体中心硬转。逐一看切入、动作中、切出和真实切换，不能只测四段各自播放。
4. 开合颌另验闭/半开/张口和嘴角/后根连接。新行为如滑行、停顿、靠近观察是额外范围，不能用标准四动作报告冒充已经覆盖。
5. 需要续做2D/生成动作时，从已接受动画的稳定动态帧取参考；首尾分别匹配切入/回接动作。只有运行时使用镜像，尾帧才可按目标游动帧镜像。生成帧流程见 `docs/FISH-TURN-WORKFLOW.md`，不替代3D引擎测试。

证据：原生循环采样、四动作与真实切换图/报告、含极端参数的完整鱼体和局部近景、至少20秒整体环绕和动作录像。模型本身在游戏里运动；生成视频不是测试录像。

工具：`volume motion-plan/build/validate` 管冻结动作输入；`validate_motion_and_surfaces.py` 管实际控制/材质；鳍177/490门、身体覆盖、材质锚定/LOD门共同复验。离散采样不宣称全连续时间无碰撞。

## 9. 最终验收材料包与顺序

先冻结最终候选及运行依赖，再收集下列证据。任何受影响文件变化，相关旧报告失效。

进入本节前完成第0.1节的一轮问题修复与合并复看；此处是集中最终验收，不是每项局部修复后的默认下一步。发现新问题先汇总该轮结果，处理完新一批后再进入本节。

| 验收层 | 必须拿什么比较 | 通过条件 |
|---|---|---|
| 来源/物种 | 已接受源资产清单、真实资料、同测位参数表、未知项 | 来源真实；物种/姿态/口开度相符；推断不冒充实测 |
| 局部形态 | 固定画布的原图/旧版/候选；灰模正侧俯腹斜；嘴、眼、鳍根近景 | 无已指出切面/尖突；口眼与物种约束一致；有限三角无翻面/裂缝 |
| 局部材质 | 未清洗原图、无光照、实际材质、身体/口内归属、供体与接头同尺度放大 | 上下颌边缘与原黑块接续正确；眼无错误重复；背腹无污染、缺块、拉丝 |

| 可交付性 | 最终文件清单、安装前后哈希、冷启动/导入日志、重放入口 | 装的就是验证过的候选；无未知shader、丢贴图、过期表或错误日志 |

### 逐鱼证据清单命令

```powershell
.\gamefactory.cmd volume sop-init --species <species_id> --output <本鱼目录>/production-review.json --json
.\gamefactory.cmd volume sop-check --review <本鱼目录>/production-review.json --output <本鱼目录>/sop.validation.json --json
```

首次建清单，之后在原清单补充实际证据；`sop-init` 不覆盖旧文件。清单固定九组必需项：准备、头、嘴、眼、身体材质、鳍、动作、运行时、整体展示。初始化全部为 `pending`，不得一次性填写为通过。返修也须记录各项实际状态，不能把未检查写成不适用。

- `candidate_files`：`source_image`、`model`、`species_profile`、`runtime_manifest`、`motion_config` 的路径和SHA256。另列实际参与运行的脚本、shader、材质表、辅助源图和LOD等依赖；模型角色指最终GLB，身体引擎资源如单独存在另列。独立唇带不得成为当前运行依赖。相对路径以清单所在目录解析。

- `stages.<阶段>`：`result`、`method`、`reviewer`、`observations` 和 `checks`。生成的每个判据列表填对应证据ID。特殊口型或独立开合颌仍须提供本物种分支依据及相应图；不删除判据来绕过审阅。

## 160：把运行时静态部件回写模型的梭鲈实验

需要减少进场静态装配时，先列出**当前实际显示的**身体、眼附件、鳍、材质、骨架及动画来源。梭鲈160把保存的手工身体、四片运行时替换鳍和两片眼部浮雕合进候选GLB及可编辑blend；旧GLB其余鳍、骨架与动画数据保持原来源。重新导入可能重排顶点并量化蒙皮权重，按位置、UV、权重、有向三角面及实际动作比较，不能用数组次序或导出成功判断等价。Godot专用材质另存共享纹理和材质资源，再由新进程读取每一份贴图；160曾出现二进制ShaderMaterial保存成功、重读却丢失贴图的失败，改为共享贴图资源与文本材质后才恢复。详细操作见[正式资产导出收尾](final-asset-export.md)，本鱼参数和复现见游戏仓库 `experiments/zander-finalization-160/README.md`。

**固化后的每一道门绑定新模型。** 新鳍网格的顶点顺序与根带可能改变，按物种解剖根线和源UV重新冻结完整根区，先做177/490鳍根，再做490整鳍膜，另验闭合身体、逐surface不透明供体、GPU覆盖、四动作与同机位外观。160候选在胸鳍局部接触修正后，根与身体门通过；整片胸/腹鳍膜在490姿态仍有约0.13–0.15mm穿入，故恢复正式游戏入口。旧版490通过记录、候选冷读成功或肉眼近似均不能覆盖这个失败；保留完整汇总与代表失败姿态，清理可重建逐帧数据，下一轮从穿入三角片修网格而非缩选区或放宽限值。

### 161 鳍根许可与自由鳍膜分开判定

用户允许梭鲈鳍根少量嵌入，但不允许摆动中其他鳍片二次穿体。先按冻结的物种完整鳍基面和微小根缝分类；根部177/490通过不能覆盖自由鳍膜失败。160四片胸/腹鳍在静止姿态即有根缝例外之外的穿入；不能事后扩大根区或提高自由面阈值。161候选保持完整根顶点不动、向外平移自由鳍并渐变过渡，参数在`zander-fin-clearance-161.json`。本机Blender/Godot实测161的490姿态完整根/整鳍膜、身体/GPU、新进程冷读与材质/动作结构均通过；仍须以物种逐鱼账本完成来源和外观等整鱼验收，不能把局部修复判为整鱼正式接受。报告、视觉对照与局限见游戏实验`zander-finalization-160/README.md`。
