# 当前鱼侧影与原材质：问题、解决办法与验收

本节来自143鱼鳍推广和144全部25鱼的对照交付。通用流程与具体鱼的通过状态分开；实际状态只读当前handoff和validation。

## 先固定实际输入

1. 从实际游戏物种清单列全本轮鱼，记录GLB、运行脚本、shader、配置及替换资源的哈希。不能把“最新实验文件”当实际安装版本。
2. 优先提取原GLB嵌入PNG字节，记录图像名称和来源。历史源图与嵌入图核对原尺寸RGBA；原字节SHA与解码RGBA一致是两个不同结论。保留原始文件，不把重新编码文件写成原字节不变。
3. 冻结每鱼原生像素/模型单位、center和实际展示缩放。带鱼、食人鱼和银龙鱼等旧模型并不使用统一宽度1，不能照搬归一化相机。

## 固定相机和展示

用实际游戏加载完成所有运行时层后的模型，停止动作，明确使用原生rest还是指定动作/开口相位。原图若张口或收鳍，比较局限单列；不移动局部去隐藏差异。侧面使用正交相机，原图与投影保持同一原生坐标、比例和共同画布。鳍或唇运输到原画布外时，双方共同增加固定留白，并保存扩边量；不裁掉突出部分，不分别自动居中/缩放配准。

标准三列：原侧面材质、正常游戏光照的侧面投影、无光照原色投影。附同坐标透明叠加、原尺寸文件和完整物种总览。布局缩略图用nearest等比缩放；纵向压缩总览会改变鱼体和鳍的形状，应回到原比例重排。二维相符不证明横向厚度、未见纹理或鳍展开量真实。

## 运行时与页面排错

| 问题/失败信号 | 解决办法 | 必须再核对 |
|---|---|---|
| `--headless`使用dummy渲染，`get_image()`为null；进程仍可能返回0 | GPU截图使用实际Godot渲染后端；无界面数值门仍可headless。仅临时渲染进程可放到屏外，正式游戏不受影响 | 拒绝日志ERROR、缺图、空图；验证图像尺寸、文件SHA并实际看图，不只看退出码或ok字段 |
| 模型材质冷读丢供体；批量原色截图有域外差异 | 材质深封装Shader和全部原生Texture；每鱼独立新进程比较原版/候选/零遮罩，遵守143原色回归 | 所有surface、实际RGBA/数组/LOD、原色域外差异；不要把未复现的批量诊断写成现有模型缺陷 |
| 页面有选鱼控件但图片404 | 按实际HTTP文档根发布图片，不能假设相对`../`会越过服务器根访问磁盘相邻目录 | 浏览器实际图片complete/naturalWidth、原尺寸链接、至少一次跨鱼切换和最终截图；图片存在于磁盘不等于页面可访问 |
| 总览与单鱼图比例不同 | 使用共同尺寸的原比例单鱼图拼接，只做等比缩放和排版留白 | 逐列共享画布；总览不单独压高度、改宽度或裁尾 |
| 截图期间其他工作更新了运行资源 | 冻结前后哈希，变化时只重出受影响鱼，报告绑定当前输入 | 不复用过期画面，不改旧失败报告为通过；保持共享工作区其他修改 |

## 交付与重放

通用工具：`resources/scripts/volume-fish/capture_side_projection144.gd`和`review_side_projection144.py`。144当前材料在游戏`experiments/blender-fish/side-projection-144`及其validation中；路径只是证据位置，不是固定新鱼输出目录。新批次应指定独立输出与发布路径，避免覆盖历史审阅。该工具的旧物种映射读取143清单，新增物种须提供自己的已接受源图/像素映射，不可套旧鱼参数或声称工具已自动支持一切新鱼。

交付前核对物种全覆盖、实际图片和页面、原尺寸打包、输入/输出SHA与游戏资产未改。记录操作者看过哪些图及局限；此步骤只交付对照，不自动修改鱼，也不新增整鱼或用户接受记录。
