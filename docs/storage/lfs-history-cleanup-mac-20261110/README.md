## 精确清单与复核

- `validation.json`：实际执行、前后磁盘统计、保护检查、远端核对与负例结果。
- `deleted-objects.jsonl`：每个已删本地对象的仓库、OID、字节数及历史路径。对象缓存路径为相应仓库 `.git/lfs/objects/<OID前2位>/<接着2位>/<OID>`。
- `protected-current-files.json`：当前路径、OID、大小及冻结 refs/index 摘要。
- `retained-exceptions.json`：来源未明和现存工作载荷匹配对象，均保留。
- `*.py.snapshot`：本次审计/隔离核对/精确执行方法的历史快照。包含固定现场路径，只作审计，不直接重放删除清单。

## 远端核对的关键限制

启用 `lfs.standalonetransferagent=baidu` 时，不能把普通 `git lfs prune --verify-remote` 的输出当成真实对象存在证明。本次隔离负例中，从未上传的对象仍被报告为 verified 并移除镜像链接；真实缓存未动。证据见 `standalone-negative-control.json`。

本次有效核对仅在独立硬链接镜像执行：每条命令临时清空 standalone adapter，临时指定原 GitHub SSH LFS 端点，使用显式直连 SSH 和默认批量大小 100。每组增加一个从未上传的唯一对象，必须确认该负例未被远端验证且镜像链接保留，才接受正例。四组不相交的游戏候选并行核对，Foundry 独立核对。`--force` 只用于隔离镜像，未在真实缓存执行。配置没有持久修改，日常传输仍走百度。

旧 Git SSH 代理路径一轮核对耗时约 725 秒且未确认任何对象；该轮结果被弃用。直连小样本和最终四组核对通过。较大 500 批次尝试未确认对象，也未用于删除。具体结果见连接调查及远端记录。

百度快照主要保存当前资产，不能宣称已删的旧本地对象都在百度。原 GitHub 远端副本在本次核对时存在，云端未删除；未来旧历史回退可能需要显式使用原 GitHub LFS 通道重新取对象，不保证默认百度链路能恢复任意旧版本。
