# 鱼类与展厅工作：外部 Agent 分工和交接

本页用于把 Fisher 的鱼类、展厅与游客工作交给使用 DeepSeek、Kimi 或其他模型的外部 CLI Agent。模型本身不负责读写仓库或运行验证；执行者须有文件、命令及所需的 Blender/Godot/GPU 访问能力。正式入口仍是 [gamefactory-toolkit](../resources/skills/gamefactory-toolkit/SKILL.md)，鱼类 3D 工作先读[完整生产 SOP](../resources/skills/fish-volume-production/references/production-sop.md)。本页是分工说明，不创建第二套任务状态。

## 工作包与依赖

| 工作包 | 可独立分派的单位 | 完成证据与前置关系 |
|---|---|---|
| 新 3D 资产 | 单条鱼；或单件景物、缸内摆件、馆内设施、人物资产 | 鱼从物种资料、已审核源图、形体、材质、骨骼到正式导出逐鱼推进；其他资产固定比例、风格、碰撞与预算，进入实际场景检查。只做 Brief / Production Delta 内的内容。 |
| 鱼的形体、骨骼与面数 | 单鱼单部位的修形/绑定；形体冻结后再做该鱼 LOD | 头、完整鳍基、鳍面、尾鳍厚度和连接先于减面与动作定版。形体、权重、材质或 LOD 变化后，按依赖重做已失效的报告。不同 Agent 不同时改同一正式 GLB/profile。 |
| 鱼鳍与尾鳍专项 | 一条鱼的一组适用鳍或尾鳍问题 | 根据该物种原图和资料确定截面、厚度、根带和运动范围；实际蒙皮表面距离、全鳍面、身体完整性及多视动态对照均要复验，不能只看闭壳或单个根点。 |
| 鱼的游动 | 单物种的姿态节奏、路线/避障、转弯/动作切换分别成单 | 先有稳定的模型和骨架；游动姿态与空间路径分开调，物种参数不互抄。原生循环、四动作、切换、实际 Godot 录像和受影响的鳍/身体门共同验收。 |
| 游客寻路 | 可达区、布局变化重算、局部避让、观赏目标、拥堵等单个问题 | 从 Fisher 已有的游客试装继续，不重建已有基础；用门洞、展缸、隔墙、动态布置与不同人数验证，并量测游客更新耗时。见[大厅 V8 记录](../projects/fishing-2d/docs/AQUARIUM-HALL-3D-V1.md)。 |
| 性能 | 一个可复现的瓶颈及其改动 | 先在同场景记录加载时间、帧耗时、CPU/GPU、绘制调用、内存与资源数量，再定位并修改。LOD、动画更新频率、批量绘制和加载缓存分别验收；方法计时不能冒充整场景 FPS。每批资产加入后复测。 |

鱼类资产、其他场景资产和游客寻路可在独立工作区并行。性能基线应先建立；鱼的形体/鳍/骨骼稳定后，再冻结该鱼的 LOD 与游动参数。每轮先整体看一遍、汇总问题、局部修复并复看，最后集中运行完整门，遵循 SOP 第 0.1 节。

## 谁做什么

- 确定性的生成、哈希、采样和验证由仓库 CLI/脚本运行，不需要模型逐项推理。
- 较低成本的外部 Agent 适合资料整理、单鱼参数初稿、范围明确的脚本修改、日志分诊、逐鱼证据清点和运行验证；能力以其实际工具与试点结果为准，不按供应商名称推定。
- 跨部位形体判断、算法接口调整、性能瓶颈归因与证据冲突需要集中审阅。多视图、原图对照和游戏画面须由执行者实际查看；Agent 的操作者审核不得写成用户本人接受。

## 任务怎样交接

使用仓库内的短任务单（例如 `plans/agent-tasks/<task-id>.md`）或等价的版本化 Issue 传递**指令**，不要用它复制 `manifest`、`progress`、`handoff`、`assets-manifest` 或 `validation report` 的状态。每张任务单只覆盖一个鱼/资产/瓶颈，写明：

1. 目标、范围、当前候选及来源哈希；相关 Brief、Production Delta、物种资料和原图路径。
2. 可修改文件和不可覆盖的基线；涉及 Foundry 与 `projects/fishing-2d` 时分别列出两个独立 Git 仓库。
3. 应运行的 CLI、专项验证和实际看图场景；`--json` 输出与报告落点。
4. 通过、失败、未知及停止条件；`ok=false`、`fix_input`、`blocked` 与运行中 job 按 toolkit 合同处理。
5. 交回代码差异、更新后的权威状态文件、代表性图片/视频、复现命令，以及本轮保留和清理的产物清单。

外部 Agent 在独立工作目录执行，避免同时修改同一鱼的模型/profile。OpenCode CLI 是一种可选执行器：接入 DeepSeek 或 Moonshot AI 后，在仓库目录选择模型并让它读取 `AGENTS.md`、toolkit 与任务单；也可使用具备同等文件、命令、图像能力的其他 Agent。不要把 API key 写入仓库。交付后先核对真实 diff、报告与游戏画面，再按用户的提交要求处理两个仓库；本仓库的“提交”包括 commit 和 push。

## 可交给外部 Agent 的 SOP 审计

按鱼运行 `volume sop-init --species <id> --output <review> --json` 建立初始待审清单；检查实际候选文件、依赖哈希、已有专项报告和九组阶段证据，补跑受影响的验证，再运行 `volume sop-check --review <review> --output <report> --json`。`sop-init` 不覆盖旧清单；旧证据不能靠改哈希复活。可让独立审计 Agent 先只读列缺项，再由执行 Agent 补证据。

`sop-check` 检查清单结构、证据绑定、缺失或陈旧项和专项报告状态，**不运行**鳍根/鳍面、身体、动作、冷读等专项门，也**不批准**视觉结果。`ok=true` 且 `next_action=human_review` 只表示清单检查通过。实际看源图、灰模、贴图、四动作、真实 Godot 画面及导出成品后，才能据实记录操作者审核；仍不代表用户接受。交付前按[资产固化与导出收尾](../resources/skills/fish-volume-production/references/final-asset-export.md)冷读正式成品，并按 SOP 完成产物清理。

## 2026-10-27 低成本模型试点

本机另有独立 PI 完整运行包；现行 Foundry 纯 CLI 仓库没有内置 PI 执行器。使用 Node 24 可启动该包。已配置的 DeepSeek 账号通过只读 `/models` 返回 `deepseek-flash` 与 `deepseek-v4-pro`，PI 的 `deepseek-flash` 最小无工具调用成功。Kimi 未在本机配置可用密钥，未实测。

用完全虚构的鳍片判定代码试验：Flash 的 `low` 档正确找出根区豁免中 `or`/`and` 错误（200 输入、1853 输出，其中1538推理 token；接口报告费用约 $0.00228）；`off` 档在另一个等价布尔表达式上给出错误判断（111 输入、30 输出；约 $0.00007）；`minimal` 档答对后一个表达式（136 输入、296 输出；约 $0.00040）。这是少量样例，不是模型质量基准。省 token 的试点先限于资料清点、日志归纳、文档初稿和明确边界的代码候选；几何接触、视觉验收、最终资产绑定与 `sop-check` 仍由本地确定性工具和主执行者复核。

PI 只读试点可用 `--tools read,grep,find,ls --no-session --no-extensions --no-mcp`；无工具测试使用 `--no-tools`。向外部 API 发送私有仓库内容须有明确授权。首次试图让 PI 直接读取梭鲈账本时，因缺少外发授权被自动审批拒绝，未发送仓库内容；用户随后明确允许发送必要片段。本轮只将约3.3 KB的梭鲈鳍证据目录、哈希和检查摘要组成受限输入包，无工具发送给Flash，没有上传模型、源图或图片像素。PI 正确区分旧源鳍切片可作为材料、旧模型对照不能直接绑定当前 v3，仍需当前轮廓/UV对照和装回身体的可见面积/遮挡数据；本地抽看旧源切片与旧对照后确认该分类合理，未据此填账本或宣布视觉通过。该次接口报告1327输入、2801输出（其中1919推理）token、费用约$0.00376。该两项小审计的输入准备与主执行者复核仍有明显开销，未证明端到端节省Codex token；要在标准化、可批量处理的资料清点或日志初筛中继续衡量。API 密钥只通过既有环境或用户配置读取，不写入仓库、任务单或日志。

用户随后允许提高推理档位和试用 Pro。用相同的3.1 KB受限梭鲈证据包及相同问题对比：`deepseek-flash` 的 `high` 档约15秒，3479总token，接口报告费用约$0.00300；结论正确区分当前v3与旧模型。`deepseek-v4-pro` 的 `medium` 档约43秒，4097总token，费用约$0.01264；其回答把当前v3的490姿态通过误说成“只是旧模型”，与包内当前模型SHA和本地正式报告矛盾。因此本次样例中Pro更慢、更贵且有关键事实错误。单题不能推断总体模型优劣，但不能按模型名或推理档位跳过输入哈希核对；此类清点先采用Flash并保留主执行者复核。

同日用户要求再试高档位后，使用 PI `deepseek-v4-pro` / `high` 做第二次只读试点。仅发送约2.2 KB的梭鲈 v3 事实包：当前模型和源图 SHA、当前490姿态技术门、冷读、八鳍遮挡数字、新发现的臀鳍源形状缺口和隐藏鳍后身体胸鳍残影、最新 SOP 70 项缺口；没有发送模型、原图或截图像素，也未开放 PI 工具。PI 此次正确区分 v3 的490通过与 v2 的旧失败，正确列出两个视觉/材质阻断项及 `sop-check` 未通过。接口报告1151输入、3473输出（其中2499推理）token，总费用约$0.01527；结果及用量保存在 `projects/fishing-2d/experiments/zander-finalization-160/work/pi-pro-high-audit.validation.json`，原始流式日志已提炼后清理。由此可让它承担有界证据清点、修复问题清单及报告映射草稿；正式图像判定、模型改动、哈希绑定和 Godot 复验仍需本地执行。两次 Pro 答案一错一对，没有证明 Pro 高档位比 Flash 更省钱或更可靠，也没有证明整体节省 Codex token。

继续试了 PI `deepseek-flash` / `high` 的身体旧鳍图案修复分诊。约 1.6 KB 事实包只含材质引用、GPU 隐藏鳍现象及门的摘要，不含图像像素或模型。它正确判断身体 albedo 保留原画胸鳍是直接原因，也提出换干净身体贴图并做实际 GPU 复看；但错误暗示 GLB SHA 不变即可沿用全部既有报告。材质改变会使材质绑定、GPU 身体覆盖、冷读和视觉证据失效，必须重跑或重新绑定。该试点 823 输入、7805 输出（含 6495 推理）token，费用约 $0.00961；报告存于 `projects/fishing-2d/experiments/zander-finalization-160/work/pi-flash-body-plan.validation.json`，原始流已提炼删除。这个输出过长，未体现 token 效率优势。后续只交给次级模型短格式、可逐项核对的证据分诊；不让其判定几何接触或验收依赖是否有效。

第三次把 70 个 `sop-check` 缺项名称作为约 3.3 KB 输入交给 PI `deepseek-flash` / `minimal`，要求短 JSON 排序。它概括了准备、头、嘴、动作、运行时等先后关系，也保留“现有报告内容未知”；但错误地把 `reviewer`、`method` 当成可从旧报告自动提取的字段。评审人和观察必须来自真实审阅，不能自动补。该次 1390 输入、896 输出（694 推理）token，费用约 $0.00149，见 `projects/fishing-2d/experiments/zander-finalization-160/work/pi-flash-ledger-triage.validation.json`。短格式降低费用与输出量，仍只适合给出待核对的工作队列，不能直接填验收账本。

PI 本机模型目录显示 `deepseek-flash` 支持图片输入，`deepseek-v4-pro` 不支持。首次给 Flash / `low` 一张仅含臀鳍四栏的局部对照图：它准确指出“改形但沿用旧描边”的鳍面内暗线、去旧描边版本相对原图缺少部分深色外沿，并明确静态图不能证明动画不穿体。接口报告 640 输入、792 输出（730 推理）token、约 $0.00114，记录在 `projects/fishing-2d/experiments/zander-finalization-160/work/pi-flash-anal-image.validation.json`，原始流已清理。这个试点支持将范围明确的截图初筛交给 Flash；同姿态接触、Godot 导入与最终视觉认可仍需实际工具和主执行者复核。

2026-10-27 梭鲈本地脚本合并检查点再试三项 Flash 工作：`minimal` 证据分诊约 $0.00083，正确缩小到报告状态和旧版来源核对；`low` 读取两段 GDScript 起草四动作截图脚本约 $0.01297，但照抄了旧冷读脚本 `set_action()` 后 `seek()` 清除待切换动作的错误，初版五张图完全相同，还须修正相机；`low` 读取两张最终 Godot 截图作明显异常初筛约 $0.00073，未发现明显缺件并明确不能推断全时段安全。三项接口合计约 $0.0145；原始 PI 流已提炼清理，实际证据见游戏实验 `local-static-merge.validation.json`。这说明短证据分诊和限范围截图初筛可交给 Flash；动作状态脚本草稿要由本地解析、运行并核对控制器快照及输出图哈希，不因代码来自次级模型省略复验。

### 2026-10-29：持续授权与对照前置检查

用户明确允许 PI 查找、处理和发送本工程任务所需内容，不逐鱼重复请求授权；凭据继续仅从本机配置或环境读取。授权被收窄或撤回时再调整。

开工选鱼前先核对独立游戏仓库的远端最新提交与逐鱼检查点。当天本地落后四个提交，误选已完成黑鲷，造成重复实验；该次废弃工作与同步耗时必须从有效对照中单列，不能作为新鱼的迁移成本。同步时先更新提交记录，LFS 只补齐实际需要的游戏依赖，避免自动下载全部历史实验。

纯本地草鱼检查点暴露了模板参数不能照搬的问题：鳍缝重合点映射需要法线区分；草鱼 mouth136_stride=1，红鲷为2；两个等价旧身体顶点须逐项核对位置、UV、法线、蒙皮及所有相关查表像素后才能共享映射。极小 LOD 三角形（叉积模长不超过1e-9）朝向可能因浮点舍入翻转，单独计数，继续检查顶点距离；正常面积三角形保留原朝向门。此类实现细节用确定性报告验证，不由模型口头判定。

本机 Blender 在受限启动环境中会提前崩溃；已安装的同一程序直接运行正常。Godot 受限进程的系统证书错误不代表模型检查失败，使用获准的本机进程重新验证。复制 Windows 脚本到 macOS 时先检查工具路径和 creationflags，避免按鱼重复发现环境问题。

本次期间用户切换了 Codex 模型，账户周用量18→20%还混有误选、同步与复核开销，不能推导草鱼精确 token 成本，也不能据此声称 A/B 净节省。次级模型的接口 token、费用、工具次数和耗时另作实测记录。

本轮最终交付草鱼175（纯GPT/本地工具）和虹鳟176（PI/DeepSeek实际执行源导出、法线保留、LOD/原生动作、材质重排与候选冷读）。虹鳟四次调用可见已完成回合合计872.92秒、接口报告$0.265887696，其中两次300秒超时；超时可能漏记未结束回合费用。主执行者随后使用其交付脚本完成绑定器复验与正式入口集成、冷读和实际看图。模型实际工作与主模型接手范围均写入逐鱼检查点。

这轮不能声称整体节省：观测到草鱼约19.8分钟、虹鳟约25.9分钟；Codex全线程区间未缓存输入174420→43177，但输出20566→30589、累计缓存请求输入12801024→16132992。草鱼区间包含换模型，两个区间还包含同步/监督/用量分析，计数不能直接换算周额度或当成因果节省。完整计数和限制保存在游戏仓库 `experiments/static-merge-model-comparison-20261029/comparison.validation.json`。

具体教训：不要让次级模型为每条鱼生成新的通用静态分析器。它新增的“从texelFetch向后看160字符寻找VERTEX_ID”误报了先前计算的索引变量；随后按真实变量链核对才通过。生成绑定器时对普通重复标识强制“只出现一次”也造成返工。模板参数应从本鱼报告导出，修改精确常量/断言；避免在重新生成全部脚本时覆盖已修正文件。Godot脚本assert不保证进程退出，包装器应看到SCRIPT ERROR便停止，90秒只作为硬兜底。任务超时后先看落盘报告：虹鳟末轮已完成材质重排与冷读，只差主执行者补跑绑定器，不应整轮重做。
