# 像素钓鱼场景：3D 水、竿和鱼的接入记录

来源：fishing-2d 的 114 → 115 → 124 迭代，2026-10-23。技术检查完成，用户视觉验收仍待确认；不代表复用鱼模型的新一轮外观批准。

## 可复用方法

- 远景与船保留 2D；水、鱼、外放鱼线在同一个 3D 世界中，才能共享深度遮挡。前景竿另用相同相机的透明视口。低分辨率视口以 nearest 整数放大，避免像素宽度不均。
- 海面大形使用方向性 Gerstner 波，细节法线、反射和泡沫分开控制。CPU 与 shader 共用时间、波参数；查询实际水高时反解水平位移，不能直接把参数平面的坐标当世界坐标。
- 深度纹理用于鱼身附近接触泡沫和水下衰减；Compatibility 的 NDC 深度换算必须单独处理。透明物体不一定写深度，不要把屏幕读取当作完整折射或流体模拟。
- 鱼跨越实际波面时在世界坐标发射水滴；速度影响强度，水滴落回同一波面后结束。涟漪应稀疏并淡出，密集白环会像标靶。
- 线的终点使用实际骨骼蒙皮点，鱼动画、姿态和镜头更新后再求连接。机械连接测试不证明鱼种解剖位置正确：下位口等物种仍需专门嘴部锚点和视觉检查。
- 鱼竿抬高、居中后再调整受力弧线；UV 程序材质可采用原像素图的黑金配色与阶梯高光。nearest 本身不能把写实软木纹理变成像素画风。
- 导环支架应沿自身局部轴缩放；旋转后直接按世界轴缩放会出现尖刺。线轴放线转动由实际放线速度驱动，不能只监听收线按钮。
- 起鱼时保留鱼的初始相机深度，再连续移向近景，避免从远处瞬间跳到镜头前。

## 复用鱼模型的验收

复用现有 GLB 和动作控制器，不修改共享模型以解决场景表现问题。保留模型原有接受状态。记录模型、动作配置、控制器和验证脚本哈希。

完整鳍基检查使用 `resources/scripts/volume-fish/validate_fin_completion.py`。默认 exporter 固定加载通用控制器；当 plan 的 `controller_script` 指向物种专用控制器时，必须显式传入 `--exporter resources/scripts/volume-fish/export_runtime_fin_roots112.gd`。124 的首次全量检查因此中止：19 种正确控制器报告保留，其余六种用正确 exporter 重跑，再逐项校验哈希后汇总。不可将控制器不匹配解释成鱼模型通过，也不能放宽阈值跳过。

身体完整性另跑 `validate_body_integrity.py`。技术通过只覆盖所采样姿态；不能替代每鱼灰模、贴图和嘴部解剖审核。

## 证据与清理

### 2026-10-24：握把与弹性竿身的转向衔接

不能只把刚性握把立即转向，而让弹性段在旧世界方向上追赶。45°瞬时转向负例在根部产生约43°折角；实际输入平滑后的540帧快速摇竿序列仍有23.88°根部折角。修复时先将方向及弹性速度从上一握把坐标系搬到当前握把坐标系，再计算新方向的鱼线受力。附加惯性从根部零值渐增到竿尖，靠近握把的前五段使用平滑柔度过渡，避免把折点移到下一段。相同GPU序列最大根部角降至0.0343°，导环翻转为0；30/60/120fps反向晃动、松力恢复和竿尖残余惯性都有回归测试。此为游戏弹性模型，不是材料参数标定。证据在 `plans/reviews/fishing-grip-continuity/validation-report.json`。

### 2026-10-24：高抬竿时导环翻转负例

将固定的握把下方向独立投影到每个弯曲切线，遇到切线接近平行该方向时会退化，越过后法向翻面。实测 15/45/78/89° 均出现相邻导环反向；78°负例点积约 -0.991。540 帧 GPU 受力抬竿序列有 8 帧翻转。沿杆每段传递最小旋转标架，导环位置、导环朝向和竿身材质共用该标架后，同序列翻转降为 0。握把方向也应由姿态解析构造，不要在竿直立时投影重力产生第二处奇点。

交互上将咬钩时的鼠标高度记录为中立点，平滑抬至约 70°，再向上最多 240 个逻辑像素达到 89.5°。鼠标初始位于屏幕底边也必须触发抬竿，不能把中立点上限限制在 840 后使底边输入仍然压竿。此改动修复已复现的导环翻面，不代表已经实现完整鱼线碰撞或松弛绳模拟。证据在游戏仓库 `plans/reviews/fishing-upright-line/validation-report.json`。

游戏仓库保留 `plans/reviews/124-fishing-water-volume/validation-report.json`、完整 plan、接触/身体检查报告、最终少量 GPU 截图及测试结果。逐姿态 `sample-*.json`、失败草稿和重复截图可在报告落盘后清理；清理清单记录数量、大小与哈希摘要。保留的报告仍是历史检查证据，删除原始采样后须重跑才能复算。

## 跃水时竿尖反向卷曲修正（2026-10-24）

复现发现，旧求解每帧从直竿开始，只迭代 12 次，稳定后的局部弯曲仍可能与导环鱼线合力矩相反（35°、70° 两组负例）。改为从随握柄搬运后的当前竿形继续求解，最多 384 次、位置松弛系数 0.04、残差小于 1e-5 提前结束。中间方案 96 次 / 0.15 在低举竿仍有振荡，不能复用。受力和画面共用线轴出线点；各导环按相邻两段鱼线方向受拉，竿尖沿实际鱼钩方向受拉，松线为零。不能靠禁止向上弯曲掩盖问题：鱼钩高于竿尖或卸载回弹时向上响应可能正常。

80 项钓鱼测试通过，含稳定弯曲与线传力矩同向、移动鱼钩的力/力矩合成及求解残差检查；高低举竿 GPU 全流程残差均小于 1e-5，接线/导环翻转/放线转轴失败为零。快速晃竿 540 帧根部最大夹角 0.0343°。仍是游戏尺度弹性模型，有限迭代及离散测试不证明所有输入。证据与哈希：`projects/fishing-2d/plans/reviews/fishing-breach-line-force/validation-report.json`，交接：`projects/fishing-2d/plans/handoffs/fishing-breach-line-force.json`；用户视觉验收待定。
