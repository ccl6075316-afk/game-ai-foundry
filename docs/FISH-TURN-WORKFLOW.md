# 鱼类转向：从银龙鱼试验推导的复用流程

适用范围：已有验收通过的游动循环，为同一鱼种追加一次转身，再接回游动。本流程不要求所有鱼共用时长、帧号或镜像策略。生成与验收仍走 [外部 Agent 协议](../resources/skills/gamefactory-toolkit/SKILL.md)，动作端点遵守 [连续动作的首尾帧规则](AI-HANDOFF.md#连续动作的首尾帧规则)。

## 1. 先确定要接回哪里，再生成转身

首次静图生成游动时，前几帧可能发生从静态设计到动态形态的调整。因此，追加转身若重新使用静图，容易得到另一个鳍形、体形或材质版本，造成两端突变。

从已验收的游动循环选一个稳定动态帧 A，作为转身首帧；先确定结束方向和回接相位 B，再用对应游动帧 B 作尾帧。A、B 可以相同，也可以不同，但运行时必须分别匹配。记录零基帧号，避免“第 9 帧”与索引 8 混淆。

如果左向游动确实由右向游动镜像实现，可以把 B 的完整画布水平镜像作为尾帧。非对称花纹、不同左右外形、独立左向游动素材，要用真实目标方向的动态帧，必要时分别生成两个方向的转身。

参考帧保留原画布、分辨率、主体位置与锚点；透明帧只合成白底，不重新绘制、紧裁主体或按卡片尺寸缩小。首尾参考都实际传入模型：

```powershell
.\gamefactory.cmd video generate --help
# 结合该子命令实际必填参数，明确传入：
# --reference-image <A-white.png> --last-frame-image <B-white.png> --no-loop-align
```

Prompt 要求一次完整转向、固定镜头、同一条鱼、鳞片与鳍形保持一致、稳定照明、尾帧匹配目标游动姿态。传了首尾参数仍需检查实际结果，不能据此直接认定接缝合格。

自动 Prompt 编写后的 handoff 也须检查：首尾约束、鱼种身份/材质、非循环动作、画布比例不能被“柔和风格对齐”等通用措辞弱化。画布尺寸须实际检查，不据 plan 声称后端必定改变了尺寸。单次 180° 转身可以进一步描述单调的姿态时间线（侧面 → 三分之四 → 正面 → 另一侧三分之四 → 目标侧面），明确禁止转过头后转回、360° 旋转或额外张嘴。检查后再提交视频生成。

## 2. 保留动作端点与统一身体尺度

转身是单次动作，不是循环。验收生成结果后，拆帧保留首尾（`--no-optimize-loop --no-trim-lead --no-trim-trail`），视频帧用 `video matte-frames --engine ai`；导入声明 `--pre-trimmed --pre-sampled`，避免再次采样、裁掉端点。默认 24 帧，复杂动作按实际需要增加。

游动和转身沿用同一原画布锚点与体长缩放。生成后端改变分辨率时，先验证宽高比例与主体占比，再补偿分辨率差；不能用两个动作各自的最大鱼身宽度重新拟合尺寸。转身中的投影宽度本来就应变化，分别拟合会制造大小跳变。

如果原画布未变，但两个端点都出现一致、轻微的等比例尺寸偏差，可以依据指定参考端点做一次固定配准，整段共用同一个比例，并在报告中保存校准前后轮廓/颜色差。红腹食人鱼试验使用固定 0.98 倍配准。禁止按每帧宽度动态归一化；偏差不是等比例、两端需要不同校准、锚点漂移或材质已经改变时，返回生成层修复。

生成素材已有透视缩短时，播放过程中不再叠加程序式横向压扁，也不在转身中途突然 `FlipH`。对称鱼的反向动作可以镜像整段；不能把“镜像尾帧”理解为“镜像即可代替转身”。

## 3. 动作时长与位移使用同一条时间轴

生成视频的时长服务于素材质量，游戏播放时长服务于动作节奏，两者可不同。设游戏转身时长为 T，转身帧数为 N：

```text
u = clamp(转身已用时间 / T, 0, 1)
frame = min(floor(u × N), N - 1)
```

朝向、位移和转身状态结束也依据同一个 T。否则会发生鱼已经朝向另一边、素材还没转完，或素材结束、移动仍在转身。

银龙鱼从约 4 秒调整到 1.6 秒后得到当前认可的节奏。下一条鱼可从 1.6 秒起试，但须按体形、摆尾和生成动作调节，不能把它当成所有鱼的固定标准。加速后需要检查是否漏掉关键姿态，必要时提高采样帧数。

## 4. 在游动中提前对齐相位，避免到墙边等一拍

只规定“到 A 才允许转身”，再按移动速度降低游动动画速度，会导致鱼到边界先减速、尾鳍变慢、等 A 出现后才转身。

正确处理顺序是：根据当前深度的安全边界估算到达转向点的时间，在仍然前进时调整游动动画速率，让 A 尽量在到达时出现。一次接近过程锁定要使用的循环，不能每帧重新选择下一圈，否则会不断推迟转向。低帧率跨过 A 时要检测并落到 A；结束从 B 继续播放，不能重置到游动第 1 帧。

摆尾速率与平移减速分别控制：靠墙减速不等于尾鳍停摆。银龙鱼的相位对齐速率限制是 0.85–2 倍，边缘余量 4 个世界单位，专用转身的减速时间参数约 0.03 秒。这些是本案例的调参结果，下一条鱼应结合体长、缩放和游动速度调整；不能把“提前准备相位”的距离直接当作必须提前转身的距离。

## 5. 将生成时的变暗与场景深度变暗分开诊断

先检查原始转身帧，再检查游戏的深度着色。银龙鱼中段源帧自身变暗，单独修改场景颜色无法解决。

本案例测量每帧不透明主体像素的亮度第 75 百分位，以首尾亮度的线性过渡作为目标，计算有限幅度的曝光 gamma；首尾 gamma 保持 1。补偿先作用于原素材，再叠加正常深度着色，保留原始素材文件。

这不是所有鱼默认需要的步骤。转面产生合理的局部明暗可以保留；若鳞片、鳍颜色或材质已经变了，应修参考或重新生成，不能靠曝光掩盖。深色鱼、透明鳍、大面积反光鱼须重新判断统计方法；大幅补偿或闪烁说明需要返回资产层处理。

## 6. 边界取决于深度和当前轮廓

鱼能与画面中的侧壁阴影重叠，是否越界取决于它所处深度的缸内空间。令：

```text
d = clamp(鱼当前深度 / 缸总深度, 0, 1)
left(d)  = lerp(前侧左边界, 后侧左内角, d)
right(d) = lerp(前侧右边界, 后侧右内角, d)
```

不要按用户设置的鱼群深度区间重新归一化；分母是缸总深度。靠前的鱼可进入更多侧壁投影，靠后的鱼活动范围收缩。当前实现保持底砂及其阴影的保守排除高度不变，不随鱼深度放宽。

再取当前实际显示帧的透明通道轮廓，应用真实缩放、镜像和旋转，得到相对精灵锚点的投影范围 `bodyMin/bodyMax`。鱼中心的允许范围是：

```text
centerMin = 当前深度水域的最小坐标 - bodyMin
centerMax = 当前深度水域的最大坐标 - bodyMax
```

这样保留原画布的非对称留白，又不会让留白参与碰撞。不要用整个画布、所有动画帧的最大宽度或最大倾斜包围盒限制日常移动；这些保守尺寸只适合初始容量/缩放保护。当前实现使用 alpha ≥ 32 的轮廓，极透明鳍应单独审查该阈值是否合适。

每帧先更新深度与展示尺度，再计算边界、准备相位和移动；动作应用后按最终姿态再校正。动画自动换帧也要校正轮廓，避免逻辑更新之后尾鳍伸出。单缸和展厅共用同一规则。

## 7. 下一条鱼的实施与验收

1. 检查已有游动，选定 A/B、目标方向和镜像资格；在现有 handoff 记录参考路径、原画布、锚点、动画名及零基帧号。
2. 在 Brief/Production Delta 声明该鱼的单次转身任务；通过 Foundry 首尾约束生成，按 workflow 的权威状态推进，验收后再抠图和导入。
3. 在 `FishTurnProfile` 为该鱼注册转身素材、切入/回接帧号、时长、可选曝光校正及有依据的固定端点配准；沿用 `FishTurnClip` 的共享相位规划、轮廓和深度边界。当前注册银龙鱼（相位 8）和红腹食人鱼（相位 12），下一条仍须增加配置，不能声称所有鱼已经接入。
4. 录制正常速度的「游动 → 转身 → 游动」，覆盖左右、靠前/靠后、中间深度、底砂附近和低帧率。检查鳍形、材质、体长、锚点、朝向、两端相位、预转身停顿、换帧越界与深度变化。
5. 保存连续录像和逐帧数据到 validation report；确认轮廓在当前深度边界内、可以进入允许的侧壁阴影、底砂排除不变。构建与相关逻辑测试通过后，仍需 Agent 审查连续动作与密集帧序列，单张截图不能证明接缝自然。技术验收可由 Agent 完成，不要求用户逐个接缝监督；用户决定最终动作审美与节奏。

## 自动检查与 Agent 审查的分工

- 流水线：输入比例与首尾参数、原尺寸导入、首尾轮廓重合/颜色差、亮度曲线、相位回接、时长、预转身低速段、深度边界、当前轮廓越界及构建测试。
- 方向模板预警：同画布下对比当前轮廓与左右参考轮廓，忽略窄正面及不确定帧，标记多次方向反转。该方法是可疑片段筛选，不能单独证明解剖正确；近乎对称鱼、位置漂移或夸张摆尾可能降低可信度。
- Agent：审查转向次数、解剖、鳍形、斑纹、嘴/眼变化、曝光是否合理及连续节奏；不合格时保留证据，只重做对应任务。
- 用户：试验阶段看最终样例、确定喜欢的节奏或新的特殊风格；已有标准的普通鱼由流水线与 Agent 先完成。无法可靠判断的新体形或连续修复仍不合格时，向用户展示具体片段和问题。

第二鱼试验工具位于 `projects/fishing-2d/plans/changes/`：`configure_turn_endpoints.py` 检查生成前合同，`review_turn_asset.py` 输出首尾/亮度/方向预警，`review_turn_capture.py` 检查运行时数据。它们目前是可复用的项目工具，由 Agent 按阶段调用，还不是 Foundry 全局自动执行的验收插件。

可直接复用：生成端点规则、统一时间轴、相位规划方法、深度边界、当前轮廓投影、换帧校正和验收方法。必须逐鱼确定：素材、A/B、左右策略、播放时长、速率范围、边缘余量和曝光需求。

## 8. 体型与节奏的沉淀（033）

体长、体形和游动节奏用于选择初始时长，不能把转向时长与真实体长直接做线性绑定：同体长的细长鱼、深体鱼和长鳍鱼，姿态变化及视觉惯性不同。当前银龙鱼保持 1.6 秒，红腹食人鱼由 1.6 秒缩短为 1.3 秒（约快 19%）。这是两条鱼的美术调参结果，不是生物学规律；下一条从相近体形的配置起步，再按完整动作检查调整。

调整时长只改统一时间轴，不删首尾、跳过切入相位或插入等待；接入相位、曝光、固定配准和深度边界继续沿用已验收配置。加快之后复查两侧相位、低帧率、提前停顿及轮廓越界。既要保存本次配置，也要保留历史报告的旧时长，避免把历史录像误写成新效果。

交付时将共享方法放入 Foundry 文档，将游戏配置、检查脚本和项目文档放入 Fisher；运行缓存、海量逐帧截图和玩家存档备份留在本机，正式素材与紧凑验证报告纳入版本库。

## 034 准备时间与转身时间分开

用户进一步确认问题是转身前的准备过长。033 的 1.3 秒只是缩短动作本身，未处理相位准备；当前食人鱼恢复 1.6 秒，历史 033 报告继续保留。

相位准备不能按素材原始 FPS 估算一整圈时间，要计入运行时 SpeedScale。食人鱼采用半圈实际播放时长作为提前量，并留足至少一个完整可达相位区间；切入仍是游动索引 12。准备时摆尾最低保持进入准备时倍率的 85%，必要时短暂加速（上限 4.5），避免为了等帧把摆尾拖慢。速率可达区间过窄时宁可增加提前量，也不能在缸边等待下一圈。银龙鱼的倍率下限策略保持原值，正常游戏回归通过。

本次最终 24 FPS / 20 秒录像的四段相位准备约 0.75–0.79 秒，12 FPS 录像约 0.83 秒，准备过程中继续游动；左右接缝、边界、动作时长和低速等待检查通过。准备时长只是相位规划区间，不能拿它推导生物学转向速度。检查准备长度和摆尾倍率应与动作长度、平移速度分开记录，否则“没有低速平移”仍可能漏掉慢摆尾。最终验证见 Fisher 的 `plans/reviews/034-turn-preparation-validation.json`。

低帧率会跨过目标动态帧，加快对齐后必须把真实切入帧呈现一帧再切换片段，避免上一张可见游动帧已是索引 13、下一张直接是转身帧 1。此保护在本次录像中对应正常帧率最长低速段约 0.08 秒、12 FPS 约 0.17 秒；不是完全零停顿，不应写成没有等待。

## 035 将体长与转身动作节奏关联

准备阶段和动作阶段独立配置。用户确认准备已经缩短后仍希望小鱼转得更快，本次保留 034 的相位准备参数，为动作时长引入真实成年体长规则：

`T = clamp(1.6 × sqrt(成年常见体长厘米 / 70) × 体形系数, 0.65, 2.4)`

70 厘米银龙鱼对应 1.6 秒；17.75 厘米食人鱼约 0.81 秒。平方根缩放避免线性缩放使极小鱼闪转、极大鱼拖太久，两端有保护范围。体形系数默认 1，可对长鳍、长身或特殊游法单独校准；当前两鱼均为 1，没有额外虚构的鱼种物理参数。这是游戏呈现规则，不能宣称真实转速已获研究验证。采用研究记录的体长，不使用卡片大小或因缸大小造成的展示缩放。

同一时长同时驱动动作采样与移动转向；不裁首尾、不跳切入相位。没有专用转身资产的鱼，其水族缸程序转向也采用同一体长规则，仍只有银龙鱼和食人鱼接入专用素材。每种鱼仍需查看完整动作、低帧率、相位和边界，尤其快动作在低帧率下显示的素材帧数会变少。最终证据见 Fisher `plans/reviews/035-body-turn-validation.json`。
