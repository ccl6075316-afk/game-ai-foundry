## 输入能确定什么

- 已接受的侧面源图为 1745×396 像素。它锁定侧视头尾轮廓、背腹**侧影**、鳍的位置和眼口在侧图中的位置。
- 资产规格中的代表体长为 200 cm，来自独立资料条目；图片像素不提供真实长度。
- 左右厚度、正面头肩宽度、背腹**横截面弧度**、另一侧鳍位和摆尾幅度是人工推断。通用构建器把 `body.sections` 的上下界与半宽连接成椭圆环，这是一种美术近似，不是解剖测量。
- 正面辅图是按像素风生成的辅助原画，不是标定过相机的正交测量图。直接投到侧图推断出的椭圆头部，不能证明两张图的眼和轮廓对应同一表面。

## 后续分析边界

1. 先确定目标正面、侧面和斜视的头肩外轮廓；不能只用侧图假定横截面是椭圆。
2. 每只物理眼只能有一处明确的几何/UV 归属，侧图眼、正图眼和附加眼面不得叠加。
3. 若使用多视图，需要记录相机和姿态假设、头/背/腹贴图分区及接缝。远端新加入的顶/腹视图能力值得评估，但尚未用于巨骨舌鱼，不能据此宣称问题已解决。
4. 新候选仍走 `volume plan → build → validate → render → 三视与游戏画面审核 → accept`。未通过视觉审核不替换游戏 GLB。

更细的试验过程见[调试会话](../../debug-sessions/2026-10-14-arapaima-head-session.md)和[架构计划](../../plans/2026-10-14-arapaima-head-ownership-plan.md)。
