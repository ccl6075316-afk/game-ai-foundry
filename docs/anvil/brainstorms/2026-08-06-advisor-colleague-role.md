# 顾问工种（ask-only 同事）

> 状态：**已确认**（用户 2026-08-06）  
> 动机：咨询「海怎么做 / 竿怎么弯 / 缺资源怎么办」时，不应污染策划会话与 `draft_brief`。

## 目标

新增可雇佣工种 **顾问**（`role_kind = advisor`）：

- 独立会话，与策划 / 项目经理 / 程序员 / IT 并列
- **只回答问题与给建议**；不写 brief、不跑制作审查/自动修/导出、不改流水线、不跑 shell 装机
- 可选只读：当前工程 brief / 文档 / 会话列表，便于结合上下文回答
- 默认锁 **Pi**（与策划同类简单 Key 路径）；首版不开放换执行器（降低写工具绕过面）

## 非目标

- 不把顾问做成第二个 IT 或第二个策划
- 不共享策划聊天上下文；协作仍靠本地文件（顾问只读）
- 不做跨会话自动注入「刚才问顾问的结论」到 brief（用户要落实时仍去策划说）
- 首版不做顾问专用 GUI 工具条（无「审/存」条）

## 用户可见行为

| 动作 | 期望 |
|------|------|
| 雇人 → 选「顾问」 | 出现新同事，独立对话 |
| 问技术/流程/资源策略 | 正常回复建议 |
| 试图「帮我改 brief / 导出 / 跑 pipeline」 | 拒绝或提示去对应工种；工具白名单硬拦 |
| 打开侧栏草稿 | 顾问会话 **不**驱动 `draft_brief` 变更 |

## 验收

1. 可雇佣顾问实例；会话落在 `plans/conversations/advisor/`
2. Pi `tool_profile=advisor`：仅只读前缀；`brief chat export|makeability|autofix|enrich` 与 pipeline mutate / shell 均拒
3. 雇人 UI 显示顾问；执行器锁定 Pi
4. 文档：`HOST-CHAT-PRODUCT` / `AGENT-ROUTING` 工种表更新为五种（含顾问）
