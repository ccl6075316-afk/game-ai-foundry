# 3D 水族馆接入经验（116）

用户要求把已有鱼接入 3D 水族馆时，应直接使用已有的真实 3D 鱼、骨骼和物种动作。最初用 billboard 鱼验证环境的方案已被用户否定，不能作为此需求的交付。

在 fishing-2d 中，116 实验通过 `AquariumFishStock.gd` 继承 `VolumeFishExhibit.gd`，复用模型加载、物种控制器、表面归属修复和自然尺寸。环境层只负责布缸、镜头与推进时间，避免复制模型修复逻辑。源模型、物种参数及原有验收结论不因场景接入而改变。

像素水可组合世界坐标量化波纹、有限高光色阶、分层水色、底部焦散和 nearest 低分辨率视口；保持鱼体轮廓可读。水色平面不等同物理折射或体积散射。鱼缸与跟随镜头应按物种真实尺寸和动作包络计算，避免大型鱼穿缸、小型鱼被邻缸挡住。

## 验证控制器必须与运行时一致

`validate_fin_completion.py` 的默认导出器 `export_runtime_fin_roots.gd` 使用通用控制器。存在物种专用控制器时，应显式传入 `--exporter resources/scripts/volume-fish/export_runtime_fin_roots112.gd`；该导出器读取 plan 的 `controller_script` 和 `controller_sha256`。116 中黑鲷、红鲷必须使用此路径。错误控制器可能被包装器报告为运行时变化，不能据此修改阈值或绕过检查。

校验输入必须匹配已安装 GLB、控制器、动作配置和实际表面修复代码的哈希。保留根区定义及来源；换模型后重跑，不能沿用旧通过结论。场景动作截图、鳍根有符号距离、身体逐 surface 不透明与 GPU 覆盖是不同检查，不能互相替代；离散采样不能证明连续时间无缺陷，最终仍需视觉审核。

116 的具体输入、报告和复现入口保存在目标游戏 `docs/AQUARIUM-PIXEL-WATER.md` 及 `plans/reviews/116-aquarium-pixel-water/`。大型逐姿态采样可在保留报告、输入和清理记录后删除；报告必须注明取证时版本与用户视觉审核状态。
