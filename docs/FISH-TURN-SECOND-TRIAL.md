# 第二条鱼转向试验：红腹食人鱼

银龙鱼的经验可以复用，但不能直接复制参数。本次完成 Foundry 生成、Agent 拒收/重试、游戏接入、运行时数据检查和视觉审查。技术验收通过，用户可直接看最终效果决定动作节奏。

## 这次推导出的补充规则

1. **首尾正确不等于动作正确。** 第一版首尾轮廓重合约 99.8%，但中段方向是右 → 左 → 右 → 左，必须拒收。加入方向模板预警，再由 Agent 审查中段解剖、鳍形、嘴部和真实转向次数。
2. **生成前审查实际 handoff。** 自动 Prompt 编写弱化了鱼种身份约束，且计划比例出现 1:1；实际第一版输出仍是 16:9，不能把计划偏差误报为已发生的尺寸改变。后续直接核对参考尺寸，并保留完整合同、显式传入输出比例。
3. **循环目标必须保存剩余帧数。** 接入试验出现约半秒预转身等待，提高速率上限仍未解决。原来的布尔“正在对齐”没有保留所选下一圈的距离；修正后持续扣减实际经过的帧数，包括循环跨帧，食人鱼低速等待消失，银龙鱼回归通过。补了相应测试。
4. **个别鱼需要模型升级或校准。** 此次 mini 两次没有遵守单次 180°，pro 版本才通过；这只是本鱼本轮证据，不证明 mini 对所有短胖鱼都不可用。轻微一致的端点尺寸偏差可固定配准，非一致漂移或材质变化须重做素材。

## 是否每条鱼都需要用户监督

普通鱼可以交给 Foundry 流水线与 Agent 完成技术处理：Agent 选参考、检查合同，流水线生成与处理，脚本检查首尾/方向预警/亮度和运行时指标，Agent 审查不合格片段并定点修复，最后交付可看的游戏样例与报告。

用户不必逐个接缝找问题，主要确定最终节奏、风格或新类型的特殊要求。遇到难以可靠判断的新体形、明显不对称角色，或连续修复仍不合格，Agent 应展示具体证据再讨论。当前新增的是项目级可复用检查脚本与逐鱼运行时配置，并非无人审查即可自动通过所有鱼的全局流水线。

共享流程见 [鱼类转向复用流程](FISH-TURN-WORKFLOW.md)。

## 033 节奏微调

用户试看片段后，红腹食人鱼转向改为 1.3 秒，银龙鱼仍为 1.6 秒。上文 032 的 1.6 秒录像和报告保留为历史证据；最新结果见 `projects/fishing-2d/output/piranha-turn-cadence-033/runtime-validation.json`。较短深体鱼可优先尝试更利落的节奏，但不能仅凭两条鱼推导通用物理公式。

## 034 准备时间与转身时间分开

用户进一步确认问题是转身前的准备过长。033 的 1.3 秒只是缩短动作本身，未处理相位准备；当前食人鱼恢复 1.6 秒，历史 033 报告继续保留。

相位准备不能按素材原始 FPS 估算一整圈时间，要计入运行时 SpeedScale。食人鱼采用半圈实际播放时长作为提前量，并留足至少一个完整可达相位区间；切入仍是游动索引 12。准备时摆尾最低保持进入准备时倍率的 85%，必要时短暂加速（上限 4.5），避免为了等帧把摆尾拖慢。速率可达区间过窄时宁可增加提前量，也不能在缸边等待下一圈。银龙鱼的倍率下限策略保持原值，正常游戏回归通过。

本次最终 24 FPS / 20 秒录像的四段相位准备约 0.75–0.79 秒，12 FPS 录像约 0.83 秒，准备过程中继续游动；左右接缝、边界、动作时长和低速等待检查通过。准备时长只是相位规划区间，不能拿它推导生物学转向速度。检查准备长度和摆尾倍率应与动作长度、平移速度分开记录，否则“没有低速平移”仍可能漏掉慢摆尾。最终验证见 Fisher 的 `plans/reviews/034-turn-preparation-validation.json`。

低帧率会跨过目标动态帧，加快对齐后必须把真实切入帧呈现一帧再切换片段，避免上一张可见游动帧已是索引 13、下一张直接是转身帧 1。此保护在本次录像中对应正常帧率最长低速段约 0.08 秒、12 FPS 约 0.17 秒；不是完全零停顿，不应写成没有等待。
